# 바자울 모바일 앱

직원 전용 Expo 앱이다. 공개 App Store·Play Store로 출시하지 않는다. 웹 프로젝트와 같은 데이터베이스와 결재 규칙을 쓰며, iOS와 Android에 동일한 코드로 배포한다. 일반 직원에게는 홈의 내 상신 진행 상황, 알림, 내 정보와 문서·첨부파일 열람을 제공한다. 직급이 시설장인 직원만 받은결재 탭과 본인 결재 순서의 승인·반려를 사용한다. 관리자 역할만으로 결재 권한이 부여되지는 않는다. 직원은 앱의 새 기안·기안함에서 서버에 등록된 양식을 직접 작성하고, 파일 첨부·임시저장·수정·상신과 본인 임시저장 기안의 삭제를 사용할 수 있다. 관리자 기능은 웹에서 사용한다. 서버는 유효한 bearer 세션, 활성 직원 상태, 현재 직급, 문서별 열람·결재 권한을 확인한다.

## 내 할 일

홈의 **내 할 일**에서 미완료·기한 초과 건수를 확인하고 목록을 연다. 미완료·기한 초과·완료·전체·삭제됨 상태와 20건 페이지 이동을 제공하며, 기한이 가까운 미완료 업무를 먼저 표시한다. 제목·선택 기한(한국 날짜)·회의명·상세 내용을 입력해 본인 업무를 등록하고 목록 또는 상세에서 완료·완료 취소한다. 상세에서는 업무 내용과 처리 이력, 변경 전후 값을 확인한다. 삭제는 대상과 보존 범위를 확인한 뒤 목록에서 제외하며 삭제된 내용·이력은 조회할 수 있다. 복원 기능은 없다.

`/api/mobile/tasks`의 조회·등록, `/[id]/completion`, `/[id]` 삭제, `/[id]/history`는 관리자도 현재 본인 담당 업무에만 접근한다. 등록 요청 식별자를 보존해 응답 유실 재시도의 중복 등록을 막고, 상태 변경·삭제에는 최신 버전을 확인해 다른 창의 변경을 덮어쓰지 않는다. 담당자가 바뀌어 접근이 거절되면 이전 내용을 화면에서 제거한다. 조회·변경 정책과 감사 기록은 웹 공용 도메인을 사용하며 원본 감사 메타데이터·IP·기기 정보는 전송하지 않는다. 서버를 먼저 배포하고 기존 1.0.5 runtime에 앱 업데이트를 배포한다. DB migration이나 새 네이티브 모듈은 없다.

## 직원 채팅

**내 정보 → 직원 채팅**에서 대화 수와 안 읽은 메시지를 확인하고 재직 직원과 일대일로 대화한다. 최신 50건부터 이전 메시지를 더 불러오며, 화면에서 실제 확인한 받은 메시지까지 읽음 처리한다. 기존 대화는 퇴직 후에도 열람할 수 있다. 새로운 메시지와 파일 전송은 현재 재직 상태와 참여 권한을 확인하며 관리자에게 다른 직원의 대화를 노출하지 않는다. 화면을 보고 있을 때 갱신하며 백그라운드에서는 개인 대화 내용을 숨긴다.

파일은 한 메시지에 하나만 첨부한다. 서버 정책의 확장자·일반 파일 용량과 ZIP 100MiB 한도를 적용한다. 큰 ZIP은 기기 내부의 고정 사본을 4MiB씩 전송하며 전체 파일을 JavaScript 메모리에 올리지 않는다. 전송 결과가 불명확하면 원래 요청으로 확인·재시도해 중복 메시지를 방지한다. 입력과 확인용 사본은 재시도 동안 보존하고, 사용자가 작성 내용 버리기를 확인하거나 계정이 바뀌면 로컬 사본을 정리한다.

PDF·이미지·텍스트 미리보기는 파일을 소진하지 않는다. 받는 사람이 파일을 저장·공유한 뒤 **파일을 저장했습니다 · 수신 완료**를 확인하면 기존 일회성 다운로드 정책에 따라 서버 파일을 삭제한다. 공유 창이 열리거나 닫힌 것만으로 저장 성공을 판단하지 않는다. 삭제 결과가 불명확하면 같은 다운로드 요청과 토큰으로 확인하고 완료만 재시도한다. 보내는 사람의 다운로드는 파일을 소진하지 않는다. 비공개 저장소 키·다운로드 토큰은 일반 응답이나 화면 주소에 넣지 않는다.

서버 `/api/mobile/chat` API를 먼저 배포한 뒤 기존 1.0.5 runtime으로 Android·iOS 업데이트를 배포한다. 새 네이티브 모듈이나 DB migration은 없다. 실제 기기의 파일 선택, 100MiB ZIP, Android 폴더 저장, iOS 공유 창과 키보드는 설치본에서 별도로 확인한다.

## 앱 아이콘

[청소년자립학교 공식 홈페이지](https://youthschool.co.kr/)의 손잡고 걷는 두 사람 심볼을 사용한다. 원본은 `assets/branding/youthschool-logo.png`에 보관하며, 글자 부분을 제외하고 원래 그림과 색상을 유지한다. 기본 아이콘은 흰 배경의 1024×1024 PNG이고, Android는 안전 영역 안에 심볼을 배치한 전경·배경·단색 레이어를 사용한다.

저장소 루트의 의존성을 설치한 뒤 `node mobile/generate-icons.mjs`로 이미지 파일을 다시 만든다. 앱 아이콘 변경은 새 APK/IPA 설치가 필요하며 EAS Update로 기존 설치본의 홈 화면 아이콘을 바꿀 수 없다.

## 문서함과 검색

하단 **문서함**에서 **제출 문서**(내가 상신한 문서), **완료 문서**(내 기안 또는 내 결재선의 승인·반려 문서), **기안함**(임시저장·회수 문서)을 전환한다. 제목·문서번호·분류·기안자로 검색하고 상태와 기간을 함께 좁힐 수 있다. 기간은 한국 시간 기준이며 제출 문서는 상신일, 완료 문서는 완료일, 기안함은 최종 수정일을 사용한다. 최신순·오래된순 정렬과 20건 단위 페이지 이동을 제공한다. 상세 화면을 닫아도 검색 조건과 페이지를 유지하며 다시 들어오면 목록을 갱신한다. 임시저장·회수 문서는 기존 기안 편집 화면으로 연결한다.

서버의 `GET /api/mobile/documents`는 로그인한 직원의 문서 권한으로만 조회하며 관리자 역할만으로 다른 직원의 문서를 노출하지 않는다. 본문·파일 저장소 경로·결재 의견을 목록 응답에 포함하지 않는다. 이 기능은 서버 API 배포와 앱 업데이트가 함께 필요하며 추가 DB migration은 없다.

## 첨부파일 저장·공유 (1.0.5)

문서 상세에서 원본과 서명본을 구분하고 모든 첨부파일을 열 수 있다. PDF·이미지는 미리보기를 유지하며 HWP·Word·Excel 등은 파일 저장 또는 공유로 해당 문서 앱에서 연다. Android의 파일 저장은 사용자가 선택한 폴더에 저장하며 같은 이름이 있으면 번호를 붙인다. iOS에서는 기본 공유 창의 **파일에 저장**을 선택한다. 다운로드 진행률·취소와 실패 후 재시도를 제공한다. 공유 창을 연 뒤 실제 전달·저장 완료 여부는 운영체제와 대상 앱에서 확인한다. 미리보기 불가 첨부가 있는 문서의 기존 앱 결재 제한은 유지한다.

`GET /api/mobile/attachments/[id]`는 안전한 파일 정보를, `/download`는 선택한 첨부 레코드의 실제 파일을 반환한다. 매번 직원 본인의 문서 열람 권한을 확인하고 관리자 역할로 접근 범위를 넓히지 않는다. 저장소 URL·키·서명 이미지는 응답에 포함하지 않는다. 기존 암호화 해제와 무효화된 자동 결재 PDF 표시를 사용한다. 공유용 사본은 앱 내부 임시 폴더에 최대 10분 보관하며 계정 변경 때 전송을 취소하고 정리한다. 사용자가 선택해 저장하거나 다른 앱에 전달한 파일은 해당 위치에서 관리한다.

`expo-sharing` 네이티브 모듈이 추가되어 새 APK/IPA가 필요하다. 넓은 외부 저장소 권한을 추가하지 않으며 추가 DB migration은 없다. Expo Web에서는 인증된 파일 저장만 제공한다.

## 문서 상세의 결재 의견과 처리 이력

반려 문서는 제목 아래에서 현재 반려 사유와 실제 처리자·처리 시간을 확인한다. 결재 진행에는 각 단계의 승인·반려·결재 대기·차례 대기, 처리 시간, 결재 의견을 표시하며 대리 승인과 대리결재 반려를 구분한다. 의견과 반려 사유는 줄바꿈을 유지하고 전문을 읽을 수 있다. 처리 이력은 최근 5건부터 표시하고 이전 기록을 10건씩 더 볼 수 있다. 날짜는 연도를 포함한 한국 시간으로 표시한다.

기존 `GET /api/mobile/documents/[id]`에 작성일·완료일, 실제 처리자 이름, 대리결재 유형과 처리 이력을 추가했다. 기존 문서 열람 권한과 결재 권한은 유지한다. 이력 응답에는 작업·처리자 이름·시간·설명만 포함하며 IP·기기·위치·감사 메타데이터를 전송하지 않는다. 서버를 먼저 업데이트한 뒤 앱 업데이트를 배포한다. 구 서버에 연결하면 기존 상세 기능을 유지하고 이력에는 서버 업데이트 안내를 표시한다. 추가 DB migration이나 네이티브 모듈은 없다.

## 임시저장 기안 삭제

기안함에서 임시저장 문서를 열어 상단 **삭제**를 누르거나 문서 상세의 하단 **삭제**를 사용한다. 대상과 영구 삭제 범위를 확인한 뒤 본인 문서와 첨부파일을 삭제하고 기안함을 갱신한다. 편집 화면에서는 현재 미저장 입력과 해당 기안의 기기 보관본도 명시적으로 버린다. 회수·상신·결재 중·완료 문서는 이 기능으로 삭제할 수 없다.

`DELETE /api/mobile/drafts/[id]`는 활성 작성자, DRAFT 상태와 `expectedUpdatedAt`을 트랜잭션 안에서 잠금 후 검사한다. 삭제 감사 기록은 문서 삭제 후에도 대상 ID와 버전을 보존하며 같은 요청의 재확인은 중복 삭제하지 않는다. 변경된 문서에는 409로 응답한다. 응답이 불명확하면 입력을 유지하고 저장·상신을 잠근 뒤 **삭제 결과 확인**으로 원래 버전을 재확인한다. 서버를 먼저 배포하고 기존 1.0.5 runtime에 앱 업데이트를 적용한다. DB migration과 새 네이티브 모듈은 없다.

## 앱 전용 기안 작성 (1.0.3)

내 상신·결재 중 문서의 상세 화면에서 **회수하고 수정**을 누르면 결재 중단과 재상신 규칙을 확인한 뒤 같은 문서의 기안 편집 화면으로 이동한다. 회수 문서는 문서함의 기안함에서도 열 수 있다. 기존 제목·양식 입력·결재자·첨부파일을 유지하며 임시저장 또는 **재상신**한다. 재상신은 기존 웹 규칙대로 결재선을 새로 시작하고 회수·이전 처리 이력은 보존한다. 승인·반려 완료 문서는 직접 수정할 수 없다.

`POST /api/mobile/documents/[id]/recall`은 작성자만 호출할 수 있으며 상세 화면의 `updatedAt`을 `expectedUpdatedAt`으로 전달한다. 문서 잠금 안에서 최신 상태와 버전을 다시 확인하므로 승인·수정과 경합하면 409로 거부한다. 동일 회수 버전의 응답 유실 재시도는 감사 이력을 추가하지 않으며, 재상신된 문서를 이전 요청으로 다시 회수하지 않는다. 앱은 확인·처리 중 중복 실행을 막고 실패 시 최신 상태 확인을 제공한다. 기안 저장의 기존 요청 식별자·버전 검증으로 재상신 재시도의 중복 문서·알림을 방지한다. 서버 배포와 앱 업데이트가 함께 필요하며 추가 DB migration은 없다.

홈의 **새 기안** 또는 **문서함 > 새 기안**을 누른다. 양식과 제목·내용을 입력하고 시설장 1명을 지정한 뒤 임시저장 또는 상신한다. 문서함의 기안함에서 임시저장·회수 문서를 다시 열 수 있다. 회의록은 안건을 여러 개 추가할 수 있고, 지출구분 등 조건에 따른 입력 항목은 서버 양식 설정을 따른다.

첨부파일은 기기 파일 선택기로 고른다. 서버의 파일 수·용량·확장자 정책을 적용하며, 직원 인증 후 발급받은 주소로 비공개 저장소에 업로드한다. 서버가 실제 파일 크기와 소유자를 확인하고 기존 암호화 설정을 적용한 뒤 문서와 연결한다. 저장 실패 시 입력과 완료된 업로드는 유지되며, 같은 요청을 재시도해도 문서·결재 알림이 중복 생성되지 않는다. 다른 화면에서 문서가 수정된 경우 덮어쓰기를 거부한다.

서버 배포 전에 PostgreSQL migration **20261002030000_mobile_draft_uploads**가 필요하다. 새 테이블의 직접 Data API 접근은 RLS로 차단한다. 모바일 직접 업로드는 기존 Supabase 비공개 저장소 설정을 사용한다. 완료되지 않은 업로드는 2시간 후 만료되며 해당 직원의 다음 작성 화면·업로드 요청에서 제한된 수량으로 정리한다.

**1.0.3은 파일 선택 네이티브 모듈이 추가되어 새 APK를 한 번 설치해야 한다.** package·서명 키·세션 저장 키·EAS 프로젝트는 유지한다. 이후 동일 런타임의 화면 수정은 EAS Update로 배포한다. 1.0.2 런타임으로 이 기능을 OTA 배포하지 않는다. 실제 운영 문서와 푸시는 테스트하지 않으며, 최종 기기 파일 선택·업로드는 사용자의 휴대폰에서 확인한다.

다른 컴퓨터의 새 폴더에서는 다음과 같이 받는다.

```bash
git clone https://github.com/frontierverse/e-approval-system.git
cd e-approval-system
git switch main
```

기존 저장소를 사용한다면 `git status`로 미커밋 작업을 확인한 뒤, 깨끗한 `main`에서 `git pull --ff-only origin main`으로 최신 내용을 받는다. 이어서 이 문서의 로컬 실행 절차를 따른다. 원래 컴퓨터의 별도 작업 폴더에는 다른 기능의 미커밋 변경이 남아 있으며 이번 모바일 반영에 포함되지 않았다.

환경변수, `google-services.json`, 인증서 개인 키 및 서버 비밀 값은 GitHub에 들어 있지 않다. EAS 자격 증명은 계정에 보관되어 있으므로 프로젝트에 로그인해 기존 설정을 사용한다. 웹 서버를 로컬에서 개발할 때 필요한 비밀 값은 기존의 안전한 경로로 별도 준비한다. APK·AAB와 로컬 검증 보고서도 GitHub 대신 EAS 빌드 및 원래 컴퓨터에 보관되어 있다.

## 로컬 실행

1. 웹 프로젝트의 PostgreSQL에 마이그레이션을 적용하고 웹 API를 실행한다.
2. 이 폴더에서 `npm ci`를 실행한다.
3. `.env.example`을 참고해 `.env.local`에 `EXPO_PUBLIC_API_URL`을 설정한다. 실제 기기에서는 컴퓨터의 LAN 주소 또는 접근 가능한 HTTPS 서버를 사용한다.
4. `npx expo start --dev-client`를 실행한다.

PDF 미리보기는 네이티브 모듈을 사용하므로 Expo Go 대신 개발 빌드가 필요하다. `npx eas-cli@latest build --profile development --platform ios` 또는 `--platform android`로 개발 빌드를 만든다.

## 알림 상태

알림함은 전체·안 읽음 필터와 최신순 20건 단위 페이지 이동을 제공한다. 알림별 **읽음** 또는 **전체 읽음**으로 상태를 변경하며, 문서를 열 때 같은 문서의 알림도 읽음으로 표시한다. 오류가 나면 상태를 먼저 바꾸지 않고 **다시 시도**를 제공한다. 하단 알림 탭에는 안 읽음 건수(100건 이상 `99+`)를 표시하고 앱 복귀·새 알림 수신·탭 재방문 때 갱신한다. 이전 계정의 늦은 응답으로 새 계정의 상태가 바뀌지 않도록 계정별로 분리한다.

`GET /api/mobile/notifications?filter=all|unread&page=1`, `POST /notifications/[id]/read`, `/notifications/read-all`, `/notifications/read-document`는 현재 직원 본인의 알림과 문서 열람 권한을 함께 검사한다. 관리자 역할만으로 다른 직원의 알림이나 문서를 보지 않는다. 문서 본문·저장소 경로·직원 개인정보는 알림 목록에 전송하지 않는다. 서버 API를 먼저 배포하며 추가 migration이나 네이티브 모듈 없이 기존 1.0.5 runtime에 EAS Update로 적용한다.


앱은 푸시 등록 실패를 내 정보의 기기 알림에 표시하고 같은 설정 의도로 재시도한다. 알림 권한을 거부한 경우 기기 설정 열기를 제공하며, 자동 등록·앱 복귀에서는 권한 허용 창을 다시 띄우지 않는다. 푸시 알림을 눌러 문서를 열 때도 서버 권한을 먼저 확인하고 실패 시 안내와 재시도를 제공한다.

앱 안의 알림 목록은 웹의 알림 데이터를 읽는다. 사용자가 `내 정보 > 기기 알림`에서 허용하면 앱은 Expo Push Token을 서버에 등록한다. 새 문서 알림은 서버에서 Expo Push Service로 보내며, 푸시 본문은 일반적인 안내만 담는다. 탭할 문서를 찾기 위한 문서 ID는 푸시 데이터에 포함된다. 로그아웃하거나 이 기기의 알림을 끄면 등록이 삭제된다.

원격 푸시 운영 순서:

1. 대상 서버 데이터베이스에서 `20260930000000_mobile_app` PostgreSQL migration의 적용 상태를 확인한다. 과거 다른 환경에서 적용한 기록만으로 운영 대상의 적용을 가정하지 않는다.
2. 연결된 EAS 프로젝트의 `app.json` 식별자를 사용한다. 앱의 EAS project ID가 빌드에 포함되어야 토큰을 받을 수 있다.
3. EAS에서 iOS APNs와 Android FCM V1 자격 증명을 설정하고, 개발 빌드 또는 내부 배포 빌드를 새로 만든다. Android 앱 설정 `google-services.json`과 FCM V1 서비스 계정 비밀 키는 서로 다른 파일이다. 앱 설정은 `GOOGLE_SERVICES_JSON` 파일 변수로, 비밀 키는 EAS의 FCM V1 자격 증명으로 등록한다. 비밀 키는 소스 폴더 밖에 보관한다. 알림은 실제 iPhone과 Android 기기에서 검증한다.
4. 웹 서버 환경에 `CRON_SECRET`을 긴 랜덤 문자열로 등록한다. Expo 프로젝트에서 push access-token 보안을 켰다면 `EXPO_ACCESS_TOKEN`도 서버에만 등록한다.
5. HTTPS 스케줄러가 10~15분마다 `GET https://www.bajaul.com/api/mobile/push-dispatch`를 `Authorization: Bearer <CRON_SECRET>` 헤더로 호출하게 한다. 이 작업은 실패한 전송 재시도와 Expo 영수증 확인을 처리한다. 서버의 새 알림은 요청 완료 후 즉시 전송을 시도한다.
6. 시험 계정으로 양쪽 기기에 로그인해 알림을 켠 뒤, 새 결재 알림을 만들고 앱 종료 상태·포그라운드·알림 탭 이동을 확인한다. 서버의 `MobilePushDelivery`에서 `ticketId`, `receiptCheckedAt`, `lastError`를 점검한다.

APNs/FCM 자격 증명, 운영 도메인과 스케줄러가 준비되기 전에는 실기기 도착까지 검증할 수 없다. 스케줄러가 없으면 즉시 전송은 시도하지만 실패 재시도와 영수증 확인은 실행되지 않는다.

## 검증

`npx tsc --noEmit`, `npx expo lint`, `EXPO_PUBLIC_API_URL=https://www.bajaul.com npx expo export --platform all`을 실행한다. 실제 기기에서 로그인, 승인·반려, PDF와 이미지 첨부를 최종 확인한다.

회수·수정·재상신은 확인 취소, 기존 입력·결재자·첨부파일 유지, 임시저장, 재상신 응답 유실 후 동일 요청 재시도, 승인·수정과의 버전 충돌을 확인한다. 웹 확인 창은 취소 버튼으로 포커스가 진입하고 내부 탭 이동과 Escape 취소를 지원하며, 닫히면 실행한 버튼으로 복귀한다. 저장 실패 시 입력을 보존하고 오류 요약으로 포커스를 이동한다. 실제 Android·iOS에서도 확인 시트의 취소·닫기와 전체 흐름을 최종 점검한다.

## 업데이트

계정 설정은 `내 정보 → 계정·도장 설정`에서 연다. 본인 이름·이메일·부서·직급을 확인하고 프로필 및 결재 도장/서명 이미지를 선택·저장·삭제할 수 있다. JPG/PNG/WEBP 원본은 4MB 이하이며 서버에서 실제 이미지 여부를 검사하고 자동 압축해 2MB 이하로 저장한다. 투명 배경 서명은 투명도를 유지한다. 모든 이미지 API는 로그인한 본인의 이미지에만 접근하며 비공개 캐시 정책을 사용한다. 서버 저장 키와 공개 파일 주소는 앱에 보내지 않는다. 파일 선택 취소·저장 실패 시 등록 이미지를 유지하고, 저장 실패 후 선택 파일로 재시도할 수 있다. 삭제는 대상 확인 뒤 실행한다.

비밀번호 변경은 웹과 동일한 현재 비밀번호 확인 및 새 비밀번호 4~128자 정책을 적용한다. 성공하면 모든 모바일 로그인 세션이 만료되어 새 비밀번호로 다시 로그인해야 한다. 계정 이미지와 전송 요청은 로그아웃·계정 전환 시 취소 및 정리한다. 계정 설정에는 새로운 네이티브 모듈이나 DB migration이 없으며 1.0.5 runtime으로 EAS Update를 배포한다.

`1.0.5`는 첨부파일 저장·공유를 추가한다. 새로운 공유 네이티브 모듈과 fingerprint runtime을 사용하므로 기존 앱을 삭제하지 않고 새 직원용 APK를 설치한다. 서버 API를 먼저 배포하며 이전 1.0.3·1.0.4 runtime에 이 코드를 OTA로 배포하지 않는다.

`1.0.4`는 바자울 공식 아이콘, 검색 가능한 문서함, 결재 의견·처리 이력, 회수 후 수정·재상신을 포함한다. 아이콘과 fingerprint runtime이 변경되어 기존 앱 위에 새 직원용 APK를 한 번 설치해야 한다. 서버 API를 먼저 배포하고 설치본을 배포한다. 기존 계정·문서·서명 키를 유지하며 추가 DB migration은 없다.

`1.0.2`부터 `expo-updates`와 EAS Update를 사용한다. 기존 APK에는 자동 업데이트 기능이 없으므로 최초 지원 설치본을 한 번 설치해야 한다. Android 직원용 APK는 `npm run build:staff`로 만들며, 기존 package와 EAS 서명 키를 유지한다. 휴대폰에서 권한이 있는 Expo 계정으로 빌드 설치 링크를 열어 기존 앱 위에 업데이트한다.

최초 지원 설치본 `1.0.2 / versionCode 3`은 [Android 설치 링크](https://expo.dev/accounts/artemismars2/projects/gyeoljaeon/builds/8cae705d-9395-48f2-8694-f9648c933ad6)에 있다. 2026-10-02 빌드와 배포 워크플로 모두 성공했으며, `staff` 내부 배포 APK·`com.gyeoljaeon.internal`·`production` 채널을 확인했다. 기존 앱을 삭제하지 않고 이 APK로 업데이트한다.

직원용 `staff` 프로필과 스토어용 `production` 프로필은 `production` 채널·환경을 사용한다. 시험용 `preview` 프로필은 `preview` 채널·환경을 사용한다. 시험용 업데이트가 직원용 앱에 전달되지 않도록 채널을 유지한다. 개발 빌드는 운영 업데이트 검증을 대신하지 않는다.

앱은 실행 시 호환되는 업데이트를 확인하고 백그라운드로 다운로드한다. 내려받은 업데이트는 다음 앱 실행에 적용한다. 결재 중 강제로 다시 시작하지 않으며, 네트워크가 없어도 설치본 또는 마지막 정상 업데이트로 실행한다. `fingerprint` runtime 정책이 네이티브 구성에 따라 호환성을 결정한다. 네이티브 모듈·권한·홈 화면 이름 등을 바꾸면 새 APK/IPA가 필요하다.

화면·문구·JS 오류 수정 배포는 모바일 폴더에서 다음 순서로 진행한다.

```bash
npm run lint
npm run typecheck
npm run update:preview -- --input message="변경 내용"
# 같은 네이티브 구성을 가진 preview 설치본에서 확인한 뒤 배포한다.
npm run update:production -- --input message="변경 내용"
```

위 명령은 EAS Workflows에서 빌드·업데이트를 생성한다. `GOOGLE_SERVICES_JSON`은 EAS 서버에서만 읽을 수 있는 파일 변수이므로, 같은 환경의 파일로 fingerprint를 계산한다. 업데이트 작업은 린트·타입·릴리스 검사를 통과해야 발행한다. `EXPO_PUBLIC_API_URL`은 빌드와 업데이트 모두 `https://www.bajaul.com`을 사용한다. 서버 비밀 값·직원 정보·세션 토큰은 업데이트에 포함하지 않는다. GitHub 푸시와 서버 배포만으로 앱 업데이트가 발행되지는 않는다. 로컬에서 직접 `eas update`를 실행하려면 동일한 Firebase 앱 설정 파일을 별도로 준비하고 runtime 일치를 확인해야 한다.

운영 배포 후 새 Android 설치본에서 앱을 완전히 종료하고 다시 열어 다운로드한 뒤, 한 번 더 종료·실행하여 적용을 확인한다. EAS Update의 runtime과 설치본의 runtime이 일치해야 한다. iOS는 별도 기기 등록과 지원 설치본 배포가 끝난 뒤 같은 절차로 확인한다. 문제가 생기면 EAS 대시보드의 해당 채널에서 이전 정상 업데이트로 롤백한다.

2026-10-02 운영 업데이트 검증: [배포 워크플로](https://expo.dev/accounts/artemismars2/projects/gyeoljaeon/workflows/01a0fa86-3eed-7bca-a572-e7ccdf46ad5c)가 성공했다. Android 업데이트 ID는 `01a0fa87-f240-7c59-9b1c-79dd2dbea06e`, runtime은 `3fbb2aedbf34795a7701a252f72d36d780405b5b`이며 직원용 Android 빌드의 runtime과 일치한다. 앱과 같은 프로토콜로 `production` 채널의 manifest와 실행 번들을 받아 HTTP `200`, 번들의 SHA-256 일치, 운영 API 주소 포함을 확인했다. 실제 휴대폰에서 새 설치본 설치와 업데이트 적용 여부는 별도 확인이 필요하다.

참고: [Expo 내부 배포](https://docs.expo.dev/build/internal-distribution/), [Apple Custom Apps](https://developer.apple.com/support/volume-purchase-and-custom-apps/), [Google Play 비공개 앱](https://support.google.com/work/android/answer/9563481), [TestFlight](https://developer.apple.com/help/app-store-connect/test-a-beta-version/testflight-overview/).


## Claude 문서 상세 v1 구현 후보 (2026-10-05)

홈 v2·문서함 v1의 공용 토큰과 Feather 아이콘을 이어, 문서 상세에 52px 헤더·본문/첨부·결재 진행/이력과 하단 처리 버튼을 적용했다. 의견 입력 후 문서번호·기안자·제목·처리 결과·의견을 확인하는 시트를 제공한다. 승인 의견은 선택이고 반려 사유는 앞뒤 공백 제외 2~2000자다. 큰 글자에서는 확인 버튼을 세로 배치하고 확인 단계의 문서 정보부터 스크롤을 시작한다.

처리 직전 최신 문서 상태·권한·버전을 다시 조회한다. 중복 탭과 처리 중 뒤로/취소를 막고, 실패·응답 유실·버전 충돌 때 의견을 유지하며 수동 최신 상태 확인 후에만 다시 처리할 수 있다. 접근 거절은 기존 문서·입력 내용을 제거한다. 회수의 `expectedUpdatedAt`, 원래 진입한 목록으로 복귀 및 검색/페이지 보존, 기존 첨부 열람·편집 화면 연결을 유지한다. 관리자 역할만으로 결재 권한을 만들지 않는다.

설계/브라우저 검수는 루트 `design-qa.md`와 `docs/mobile-document-detail-design-brief.md`에 기록했다. 로컬 구현 후보이며 운영 EAS Update는 별도 단계다. 새 네이티브 모듈이나 서버 변경은 없다. 실제 기기의 동적 글자 크기·키보드·스크린리더와 업무 처리 후 최종 동작은 후속 확인한다.
