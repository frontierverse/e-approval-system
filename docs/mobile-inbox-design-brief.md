# Claude Design 전달 바자울 모바일 받은결재 v1

기준일 **2026-10-05 한국시간**, 운영 main **17e4add**. 기존 Claude 작업 **바자울 전자결재 앱 디자인**의 새 페이지 **받은결재 v1**을 만든다. 홈 v2·문서함 v1·문서 상세 v1·기안 작성 v1은 실제 앱에 적용해 서버와 Android·iOS production OTA를 배포했다. 이번 요청은 시설장 전용 받은결재 목록의 디자인과 검토용 모의 프로토타입이다.

## 목적과 범위

시설장이 자신에게 배정된 대기 결재의 전체 규모를 파악하고, 검색·상신일 기간·정렬로 필요한 문서를 찾아 기존 상세 화면으로 들어가게 한다. 새 페이지에서 홈·문서함의 시각 체계와 Feather 선형 아이콘을 이어간다. 완료한 다른 페이지는 보존한다. 운영 API·실제 로그인·직원 및 업무 자료·푸시·앱 코드·DB·배포는 이번 작업에서 사용하거나 변경하지 않는다.

첨부 자료는 이 브리프, UI/UX 가이드라인, 최신 기능 계약, 적용된 홈 스타일, 현재 받은결재의 기능 참고 캡처다. 최신 기능 계약을 과거 시안의 가정보다 우선한다. 현재 받은결재 캡처의 이전 남색·큰 헤더를 스타일 기준으로 복제하지 않는다.

## 사용자와 권한

- **현재 직급이 시설장**이고 서버의 `canApproveDocuments=true`인 직원만 받은결재 탭에 접근한다. 일반 직원·팀장·관리자 역할만으로 탭이나 목록을 제공하지 않는다. 관리자도 현재 시설장 직급이 아니라면 접근할 수 없다.
- 목록에는 로그인한 직원의 **PENDING 결재 단계**가 있는 SUBMITTED/IN_PROGRESS 문서만 들어온다. 다른 직원 전체 문서·완료 문서·임시저장·회수 문서는 아니다.
- 매우 중요한 경계: **목록에 보이는 모든 문서가 지금 처리 가능한 문서는 아니다.** 과거 다단계 문서의 본인 차례 전 대기도 포함될 수 있다. 목록 API에는 `canDecide`나 전체 결재선·현재 단계가 없고 `stepOrder`는 본인의 대기 단계 순서일 뿐이다. 이를 ‘내 차례’, ‘즉시 승인 가능’, ‘2/3 진행’으로 해석하지 않는다. 처리 가능 여부는 기존 상세에서 최신 권한·상태·순서를 확인한다.
- 권한 거절·세션 만료·계정 변경 상태에서는 이전 계정의 목록·검색 결과를 노출하지 않는다. 단순 연결 실패와 구분한다. 이는 새 시안의 안전 기준이며 모든 상태가 현재 화면에 이미 구현되었다는 뜻은 아니다.

## 첫 화면과 목록

작은 헤더에 **받은결재**, 현재 결과 건수와 갱신 행동을 압축한다. 이어 검색·간결한 기간/정렬 컨트롤, 실제 업무 행을 둔다. 기본 목록의 첫 행은 390×844에서 전역 Safe Area·탭바를 제외한 콘텐츠 상단 40% 이내에서 시작하게 한다. 영웅 문구·장식 이미지·큰 통계 카드·중복 ‘대기 중’ 제목을 넣지 않는다.

응답 `total`은 **현재 적용한 조건의 결과 건수**다. 필터 중 전체 대기 건수처럼 표시하거나 검색 결과와 더하지 않는다. 조건이 없을 때는 대기 n건, 조건이 있을 때는 검색 결과 n건으로 구분할 수 있다. API에 없는 ‘오늘 마감’, ‘긴급’, ‘미처리 일수’, ‘승인 대기/내 차례’ 별도 카운트를 만들지 않는다.

행의 우선순위는 제목 → 상태·기안자·상신 시각 → 문서번호·첨부 개수다. 제공되는 정보만 쓰고 긴 한글 제목이 상태를 밀어내지 않게 한다. 반복 행에 큰 카드·별도 보기 버튼·직원 아바타를 붙이지 않는다. 문서번호가 비어 있거나 상신 시각이 없으면 존재하지 않는 값을 만들지 않는다. 날짜를 표시할 때 한국 시간과 연도를 유지한다.

상태는 `submitted=상신`, `in_progress=결재 중`이며 승인/반려 완료 상태를 이 대기 목록에 섞지 않는다. 색상만으로 구분하지 않는다. 본인 단계 번호를 표시한다면 ‘내 결재 단계 2’와 같이 의미를 한정하고 전체 단계 수·현재 차례를 추측하지 않는다. 한 단계 문서에서는 불필요한 단계 수 장식을 생략할 수 있다.

## 검색과 기간

- 검색어 최대 **100자**, 공백 정리 후 명시적으로 검색한다. 제목·문서번호·분류·기안자를 서버에서 대소문자 구분 없이 검색한다. **분류는 검색 가능하지만 행 응답에 분류명은 없다.** 행에 분류 칩이나 별도 분류 목록을 만들지 않는다.
- 편집 중인 검색어/기간과 **적용한 조건**을 구분한다. 적용 전 검색 결과 건수·현재 목록을 새 조건의 결과로 바꾸지 않는다. 검색 중 과거 응답이 최신 조건을 덮어쓰지 않게 한다.
- 기간은 **상신일 기준 한국 날짜**이며 시작·끝은 선택이다. 한쪽만 입력해도 가능하다. 실제 달력 날짜와 YYYY-MM-DD, 시작≤끝을 검사한다. 오류 후 입력을 유지하고 오류로 포커스를 안내한다.
- 기간 패널/시트에는 시작일·종료일·적용·기간 지우기·취소/닫기가 필요하다. 취소는 적용된 기간을 변경하지 않는다. 열려 있는 기간 UI가 목록을 가릴 수 있으므로 기본 화면은 닫힌 상태다.
- 별도 상태 필터·기안자 드롭다운·부서 필터·기간 프리셋·마감순·승인 이력 탭은 현재 계약에 없다. 새 기능처럼 추가하지 않는다.
- 초기화는 검색·기간을 비우고 최신순·1페이지로 돌아간다. 정렬은 **최신순/오래된순**, 검색·기간을 유지하며 1페이지로 돌아간다. 검색·기간 적용도 1페이지로 돌아간다.

## 페이지 이동과 갱신

페이지 크기는 **20건**이며 무한 스크롤로 바꾸지 않는다. 총 2페이지 이상일 때 이전/현재·전체 페이지/다음을 제공한다. 처음·마지막과 조회 중에는 해당 이동을 비활성화한다. 0건도 API상 1/1이나 빈 화면에 의미 없는 페이지 도구를 반복할 필요는 없다.

상세를 닫으면 원래 받은결재 검색·기간·정렬·페이지를 유지하고 목록을 갱신한다. 상세에서 승인·반려되어 목록에서 빠지거나 다른 기기의 처리로 마지막 페이지가 사라지면 서버가 반환한 실제 페이지로 보정한다. 상세의 결재/회수 기능과 권한은 이미 완성된 문서 상세 v1을 사용한다. 새 상세 화면을 재설계하지 않는다.

다시 진입·탭 재방문·사용자의 새로고침/당겨서 갱신을 지원한다. 첫 조회에는 최종 목록과 같은 밀도의 로딩을, 같은 조건의 재조회에는 기존 결과를 유지하며 작은 진행 표시를 제공한다. 재조회 실패는 ‘이전에 불러온 목록’임을 명확히 안내하고 재시도를 제공한다. **단순 연결 실패의 기존 결과 유지와 권한 실패의 결과 제거를 혼동하지 않는다.** 다른 조건의 결과를 새 조건 아래에 보여주지 않는다.

## 탭바와 스타일

하단은 **홈 → 받은결재 선택 → 문서함 → 알림 → 내 정보**다. 일반 직원 권한 변형에서는 받은결재 탭 자체가 없고 홈으로 안내한다. 새 기안은 별도 탭이 아니다. 각 탭의 접근 이름과 선택 상태, Safe Area를 보존한다. 읽지 않은 알림 배지는 별도 알림 기능의 건수이며 받은결재 total과 관련 없다. 예시는 검수용 알림 **3건**으로 명시한다.

적용된 HomeTheme 토큰과 Feather 아이콘을 사용한다. 흰/어두운 표면, 얇은 테두리, 절제된 파란 선택/주 행동, 44px 이상의 상호작용 영역을 유지한다. 기존 컨트롤 보더는 약한 구분선과 다른 대비를 가진다. UI 가이드의 글자 4.5:1, 큰 글자/경계 3:1과 키보드 포커스를 라이트·다크에서 확인한다.

## 산출물과 필수 검수

새 페이지 **받은결재 v1**, 편집 가능한 소스 ZIP, 작동하는 모의 프로토타입, 대표 상태 캡처와 실제 검수 결과를 제공한다. 검수 컨트롤과 모의 데이터 표시는 앱 화면 밖에 둔다. 외부 요청·운영 자료·실제 업무 변경은 하지 않는다.

1. 기본 23건과 20건 페이지 이동, 1건, 전체 대기 0건, 조건 결과 0건, 큰 건수와 긴 제목.
2. 제목/문서번호/기안자/분류 검색, 적용 전 입력, 검색 초기화, 빠른 조건 변경에서 최신 응답만 반영.
3. 기간 열기/취소/적용/지우기, 한쪽 날짜, 실제 윤일, 존재하지 않는 날짜, 역전 오류 후 입력 보존.
4. 최신순/오래된순과 조건 유지, 1페이지 초기화, 이전/다음 경계와 조회 중 중복 이동 방지.
5. 행 열기 → 기존 상세 목적 확인 → 돌아오기와 조건/페이지 보존, 처리 후 행 제거·마지막 페이지 보정의 모의 상태.
6. 최초 로딩, 같은 조건 재조회, 최초 오류, 재조회 실패 후 기존 결과 안내/재시도, 권한 403·세션 만료·계정 변경의 데이터 제거.
7. 일반 직원/시설장 아닌 관리자에게 받은결재 탭·목록 미제공, 단계 2를 즉시 결재 가능으로 표시하지 않기.
8. **390×844·360×800·라이트/다크·200% 상당 큰 글자·검색/기간 입력 시 가상 키보드**. 목록 기본 화면 첫 행 위치, 가로 넘침, 제목/건수/컨트롤 겹침, 잘림, 44px 대상과 접근 이름을 실제 렌더로 확인.
9. 키보드 포커스·오류 이동·확인/취소가 가려지지 않기, 시트를 쓰면 진입/내부 이동/Escape·Back 취소/복귀.
10. DOM/가상 키보드/화면 배율의 검증과 실제 iOS·Android OS·동적 글자/스크린리더 확인을 구분하고 미확인 항목을 그대로 기록.

목록에는 승인·반려·일괄 승인·스와이프 결재·삭제·회수·재상신·첨부 미리보기/다운로드를 추가하지 않는다. 모두 기존 상세/작성 흐름과 실제 서버 권한 검사를 따른다. 알림·내 정보·로그인·다른 업무 화면은 이번 설계 범위 밖이다.

## 구현 반영 기록 — 2026-10-05

이 문서의 main 17e4add와 전달 범위는 Claude 설계 요청 당시의 기록이다. 완료된 **받은결재 v1** 소스와 대표 캡처를 후속 작업에서 실제 Expo InboxScreen에 반영했다. 실제 API 계약·기존 상세·세션 보호를 유지하며 검색·기간·정렬·20건 페이지 이동과 로딩/오류/권한 상태를 구현했다. 공용 조회 훅은 계정별 결과 분리, 401/403 캐시 제거, 중복 갱신 방지와 조회 시각 보존을 보강했다.

실제 화면 비교 및 상태 검수는 저장소 루트 design-qa.md를 따른다. Android·iOS·웹 번들 생성은 통과했다. 실제 휴대폰의 OS 키보드·동적 글자·스크린리더·운영 연결과 운영 배포 완료는 별도 검증이다.
