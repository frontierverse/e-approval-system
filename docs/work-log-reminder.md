# 출근부 오전 작성 알림

근무일 오전에 전 직원에게 출근부 작성을 안내한다. 작성 여부와 개인 휴가 여부는 확인하지 않는다.

## 발송 정책

- 한국시간 월~금 오전 9시부터 10시 전까지 기존 정기 푸시 작업의 첫 정상 실행에서 생성한다. 토요일·일요일·공휴일·대체공휴일에는 보내지 않는다.
- 대상은 기존 직원 푸시 정책의 `ACTIVE` 직원 전원이다. 퇴사일이 당일이거나 지난 직원, 비활성 직원은 제외한다.
- 알림 문구는 `오늘 출근부를 작성해 주세요.`이다.
- `MobilePushEvent`의 `WORK_LOG_REMINDER` 종류를 사용한다. 직원별 한국 날짜별 이벤트 키와 기기별 발송 기록으로 중복을 방지한다.
- 유효한 모바일 로그인 세션과 푸시 구독이 있는 기기에 전송한다. 실제 휴대폰 수신에는 앱 설치와 알림 권한이 필요하다.
- 새 알림은 한국시간 09:00~09:59에만 생성한다. 오전 10시에 만료되어 이후 재시도로 늦은 알림을 보내지 않으며 Expo에도 남은 유효 시간을 전달한다.
- 알림을 누르면 기존 인증된 이벤트 열기 API를 거쳐 모바일 `/work-logs`로 연결한다.

## 정기 실행과 인증

기존 직원 알림은 Supabase의 `pg_cron`·`pg_net`으로 `GET https://www.bajaul.com/api/mobile/push-dispatch`를 15분마다 호출한다. 작업 이름은 `bajaul-employee-push-dispatch`, 스케줄은 `*/15 * * * *`다. 새 출근부 알림도 이 정기 처리에서 생성하여 같은 발송 큐를 사용한다. 정상 실행이면 09시 첫 호출에서 처리되며 실행 지연이 발생할 수 있다. 휴대폰의 도착 시각은 보장되지 않는다.

`scripts/configure-mobile-push-cron.mjs`는 서버의 `MOBILE_PUSH_CRON_SECRET`을 Supabase Vault의 `bajaul_mobile_push_cron_secret`에 저장하고 정기 실행 작업을 준비한다. 운영 서버와 Vault에는 같은 값이 필요하다. `/api/mobile/push-dispatch`는 `MOBILE_PUSH_CRON_SECRET`을 우선 사용하고, 없는 기존 환경에서는 `CRON_SECRET`을 사용한다. 값이 없거나 `Authorization: Bearer …` 헤더가 일치하지 않으면 HTTP 401을 반환한다. 비밀값을 저장소·클라이언트·로그에 노출하지 않는다.

루트 `vercel.json`의 `/api/internal/resource-maintenance` → `0 18 * * *` 설정은 기존 자료실 정리 작업이다. 이 작업은 `CRON_SECRET`로 인증한다. 출근부 알림 추가에는 별도 Vercel cron이 필요하지 않으며, 기존 스케줄과 인증키를 유지한다.

## 운영 적용

1. 서버 변경을 Production에 배포한다. 기존 `MobilePushEvent`·발송 대기열을 사용하므로 이 기능 자체를 위한 Prisma 스키마 변경이나 DB migration은 없다.
2. 모바일 `/work-logs` 경로를 허용 목록에 추가한 변경을 production 채널에 발행한다. 알림 선택 시 출근부 화면을 여는 데 필요한 앱 업데이트다.
3. 운영 Vercel 프로젝트와 Supabase Vault의 기존 푸시 전용 인증값이 일치하는지 확인한다. 자료실 정리의 `CRON_SECRET`은 변경하지 않는다.
4. Supabase Cron의 `bajaul-employee-push-dispatch` 작업이 `*/15 * * * *`로 활성화되어 있는지 확인한다. 이미 운영 중이면 재설정하지 않는다. 미등록 환경에서 `scripts/configure-mobile-push-cron.mjs`는 기본적으로 비활성 작업을 준비하고 `--activate`를 사용한 실행이 활성화한다.
5. 다음 정상 근무일 Runtime Logs와 발송 대기열을 확인한다. 운영 API를 수동 실행하면 실제 직원 알림이 생성되므로 테스트 목적으로 호출하지 않는다. 기기에서 업데이트 적용과 알림 선택 후 화면 이동도 확인한다.

정기 푸시 처리에서 새 알림과 재시도를 함께 발송한다. 오전 10시 이후에는 출근부 알림이 만료된다. 소스와 스케줄 정의만으로 운영 배포·작업 활성화·실제 기기 수신이 확인되지는 않는다. 운영 적용 기록에는 서버 배포, 모바일 업데이트, 실제 cron 활성 상태를 각각 확인한 결과를 남긴다.

## 공휴일 유지보수

검증된 2026·2027년 공휴일은 `src/lib/work-log-reminder-core.ts`에 기록되어 있다. 정부가 임시공휴일을 지정하면 해당 날짜를 추가하고 배포한다. 매년 다음 해 공식 월력요항을 확인한 뒤 새 연도의 전체 공휴일을 추가한다. 아직 검증하지 않은 연도에는 `unsupported-year`로 알림을 중단하여 공휴일에 잘못 보내지 않는다.

정부 임시공휴일 발표 또는 연도 변경 후에는 주말, 공휴일, 대체공휴일, 정상 근무일, 한국시간 09시 경계와 중복 실행 테스트를 확인한다.
