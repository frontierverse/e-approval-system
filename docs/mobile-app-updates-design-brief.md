# 바자울 모바일 앱 업데이트 v1 디자인 브리프

기준: **2026-10-06 / 운영 main 67804ba00877af9da0f6fca65e62dbd28182ae12 / 계정·도장 설정 v1 반영 이후**. 기존 Claude 작업 **바자울 전자결재 앱 디자인**에 아홉 번째 페이지 **앱 업데이트 v1**을 추가한다. 홈 v2·문서함 v1·문서 상세 v1·기안 작성 v1·받은결재 v1·알림 v1·내 정보 v1·계정·도장 설정 v1은 보존한다.

## 목적·범위

직원이 이 기기에서 업데이트 상태와 다음 행동을 빠르게 이해하고, 현재 실행 중인 코드와 다운로드해 적용을 기다리는 코드를 구분하도록 한다. 내 정보 → **앱 업데이트**(`/app-updates`)로 진입한다. 로그인 화면·전역 업데이트 안내에서도 열 수 있는 공통 경로이며 로그인 여부와 무관하게 기기의 업데이트 상태를 보여준다. 다른 계정의 정보나 업무 내용이 필요하지 않다.

디자인·모의 프로토타입만 만든다. 실제 Expo 업데이트 확인·다운로드·재시작, 운영 API·로그인·직원 데이터·앱 저장소·DB·소스·배포는 사용하거나 변경하지 않는다. 실제 앱 반영과 배포는 Codex가 별도로 진행한다. 새 컴퓨터 폴더나 권한 연결도 필요 없다.

첨부 01은 이 브리프, 02는 UI/UX 검수 기준, 03은 최신 소스로 확인한 기능 계약이다. 04·05는 적용된 홈·계정 설정의 스타일 참고이고, 06·07은 현재 Expo 웹 화면의 기능 참고다. 웹 참고 화면은 업데이트가 **비활성**인 실제 동작이며 네이티브 다운로드 상태를 검증한 캡처가 아니다. 최신 계약이 기존 시안의 가정보다 우선한다.

## 구조·시각 언어

Safe Area를 고려한 **뒤로 + 앱 업데이트**의 간결한 52px 안팎 헤더를 쓴다. 별도 탭바, 거대한 업데이트 아이콘·히어로·중복 제목을 넣지 않는다. 뒤로는 이전 화면으로 돌아가며 이전 화면이 없으면 로그인 상태에 따라 내 정보/로그인으로 연결하는 모의 동작이다.

순서는 **현재 상태와 다음 행동 → 현재 적용된 업데이트 → 확인·다운로드 기록**이다. 앱 표시 버전은 작게 함께 보여준다. 상태와 주요 행동은 첫 화면 상단에서 바로 찾을 수 있어야 한다. 의미 있는 섹션만 그룹 표면으로 묶고, 반복 메타데이터는 간결한 행으로 정렬한다. 16px 바깥 여백·12~16px 그룹 간격·얇은 경계·HomeTheme 라이트/다크 토큰·Feather 선형 아이콘을 이어간다. 기본 버튼은 44px 이상이며 작은 화면과 큰 글자에서는 행 높이와 줄바꿈을 허용한다.

상태는 색과 글자를 함께 쓰고 파란 주 행동, 차분한 중립 상태, 실제 완료에만 절제된 성공 색을 사용한다. 전역 상태 안내는 이 화면에서 중복하지 않는다. 런타임·배포 채널·서버 주소·전체 배포 ID·캐시 삭제·자동 업데이트 설정을 새로 노출하지 않는다. 릴리스 노트·용량·남은 시간·다운로드 속도·스토어 버튼은 계약에 없다.

## 상태와 행동

| 상태 | 표시·행동 |
| --- | --- |
| idle | **현재 버전 사용 중**. **업데이트 확인**. 최신임을 확정한 상태가 아니다. |
| checking | **업데이트 확인 중**, 해당 행동 **확인 중…** 및 잠금. 기존 업무는 유지된다. |
| downloading, 0~99% | 실제 진행률과 진행 막대, **다운로드 중…** 및 잠금. |
| downloading, 진행률 null | **업데이트 다운로드 중**, 진행률 확인 중 안내/작은 표시. 가짜 숫자·고정 막대를 만들지 않는다. |
| downloading, 100% | **다운로드 100% · 마무리 중**. 완료·적용으로 바꾸지 않는다. |
| available | **새 업데이트 다운로드 가능**, **업데이트 다운로드**. 처리 중이 아니면 작은 **새 업데이트 다시 확인** 보조 행동. |
| error, available 없음 | **업데이트 확인 필요**, 오류와 **업데이트 다시 확인**. |
| error, available 있음 | 마지막 다운로드 대상 보존, 오류와 **다운로드 다시 시도**. **새 업데이트 다시 확인**도 처리 중이 아닐 때만 제공한다. |
| ready | **다운로드 완료 · 적용 대기**. 아래의 안전한 적용 안내. **업데이트 적용 / 나중에**. 미저장 입력·진행 중 요청이 있으면 적용 잠금. |
| disabled | **설치한 앱에서 확인할 수 있습니다**. **웹·개발 화면에서는 앱 업데이트를 확인하거나 다운로드하지 않습니다.** 네이티브 행동 없음. |

**업데이트 확인**은 새 업데이트가 있으면 이어서 다운로드한다. 새 업데이트가 없으면 현재 버전 사용 중으로 돌아간다. 기존 provider에는 성공적인 ‘최신 버전 확정’ 결과가 별도 보관되지 않으며, 최근 확인 시각은 실패한 시도일 수도 있다. 따라서 idle·기록 없음·최근 확인 값만으로 **최신 버전입니다**를 만들지 않는다.

진행률은 실제 유한한 0~1 값만 쓰고 표시할 때 내림한 백분율을 사용한다. 0%와 미확인은 서로 다르다. 100%가 되어도 provider가 ready를 확인할 때까지 마무리 중이다. 연타·네이티브 시작 절차·기존 확인/다운로드와 겹치는 요청은 하나의 잠금으로 막는다. 뒤로 나가도 업데이트를 취소하지 않으며 이전 업무 입력을 버리지 않는다.

2026-10-07 사용자 요청으로 ready 동작을 확장했다. **업데이트 적용**을 누르면 앱이 직접 재시작하며, **나중에**는 다운로드를 유지하고 안내를 숨긴다. 작성·처리 중 작업이 있으면 이유와 함께 적용을 잠근다. 현재 코드 정보는 실제 다음 실행에서만 바뀐다. [현재 기능 계약](mobile-app-updates-design-contract.md)을 따른다.

## 버전·시각의 의미

- **앱 버전**: 현재 설치 구성의 표시 버전. 기본 합성 예시 `1.0.5`. OTA를 받았다고 `1.0.6`으로 바뀌지 않는다.
- **코드 버전**: 현재 실행 중인 업데이트 ID의 앞 8자. 설치 포함 기본 버전이면 **설치 파일에 포함된 기본 버전**, 정보 없으면 **확인 불가**. 메인 합성 코드 `demo10a1`.
- **게시 시각**: 현재 실행 중인 코드의 게시 시각. 다운로드 대상 게시 시각과 섞지 않는다.
- **이 기기에서 적용 확인**: 이 상태 기능이 현재 코드의 실행을 처음 관찰한 시각. **실제 설치 시각과 다를 수 있습니다.**를 간결하게 유지한다.
- **최근 확인 시도**와 **최근 다운로드 확인**은 별개의 기록이다. 시도와 성공을 혼동하지 않는다.
- **새 업데이트 게시 시각**은 available/downloading/ready에서만 표시하며 ready는 downloaded, 나머지는 available에서 읽는다.

기록 없음·잘못된 날짜는 **확인 기록 없음**이다. 시각은 한국시간으로 표시하고 긴 시각·기본 버전 안내를 잘라 핵심을 숨기지 않는다. 합성 값만 쓴다. 기본 버전으로 비상 복구해 실행 중이면 현재 적용된 업데이트 섹션에서 기존 복구 안내와 네트워크 확인/재확인 의도를 유지한다. 정상 최신 버전으로 단정하지 않는다.

기기 기록 저장 실패는 **업데이트 시각을 기기에 보관하지 못했습니다. 이번 실행의 상태는 확인할 수 있습니다.**를 기록 섹션에서 알린다. 업데이트 확인/다운로드 행동은 계속 사용할 수 있고 기술적 오류·파일 경로·자격 증명을 표시하지 않는다.

## 대표·추가 검토

메인 **390×844 라이트**, idle, 앱 버전 `1.0.5`, 현재 코드 `demo10a1`, 합성 게시 시각 `2026. 10. 5. 오전 9:00:00`, 적용 확인 `2026. 10. 5. 오전 9:30:00`, 최근 확인 `2026. 10. 6. 오전 2:30:00`, 최근 다운로드 `2026. 10. 5. 오전 9:05:00`. 실제 운영 코드/기기 기록이 아니다.

추가: 360×800 다크, 200% 상당 큰 글자, 기록 없는 첫 실행, 설치 포함 기본 버전·버전 확인 불가, 확인 중, 다운로드 0/37/100%·미확인 진행률, 다운로드 가능, 확인 실패·다운로드 실패·재시도·연타, ready 후 모의 재실행, 비상 복구 실행, rollback 준비, 기기 기록 저장 실패, 로그인 전/후 뒤로, 화면 이탈 후 늦은 응답을 검토한다. 모의 상태·네트워크·재실행 제어는 앱 화면 밖에 둔다.

**앱 업데이트 v1** 페이지, 대표/주요 상태 PNG, 동작하는 모의 프로토타입, 편집용 소스 ZIP **`bajaul-app-updates-v1-source.zip`**, 검수 결과와 미확인 항목을 제공한다.

- 390×844·360×800, 라이트/다크, 200% 글자에서 가로 넘침·겹침·행동 가림 없음. 필요한 실제 정보는 세로 스크롤로 접근.
- 상태/다음 행동이 먼저 보임. 44px 행동, 읽기 순서·하나의 주 제목, visible focus, 일반 글자 4.5:1 대비.
- 확인→다운로드, 100% 마무리→실제 ready, 다운로드와 실행 버전 구분, 시도/다운로드/관찰 시각 구분.
- 처리 중 잠금·다운로드 실패 대상 보존·의도에 맞는 재시도·기록 저장 실패의 비차단 동작.
- ready·disabled에 네이티브 실행 버튼 없음. 공통 경로·뒤로·탭바 없음.
- DOM/모의 검토와 실제 iOS/Android·native 업데이트 API·SecureStore·앱 재실행·스크린리더·운영 배포 검증을 구분한다. 실제 미확인은 그대로 기록한다.
