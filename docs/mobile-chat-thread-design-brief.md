# 바자울 모바일 직원 대화방 v1 디자인 브리프

2026-10-06. 기존 Claude 디자인 작업의 현재 11개 페이지를 보존하고 **직원 대화방 v1** 페이지를 추가한다. 기존 직원 채팅 목록 v1과 홈·내 정보의 시각 언어를 이어간다. 합성 자료를 사용하는 디자인과 모의 프로토타입이다. 실제 앱 반영과 배포는 Codex가 담당한다.

## 화면의 목적과 구조

직원 한 명과 주고받은 내용을 확인하고 메시지 또는 파일 한 개를 보낸다. **뒤로 → 상대 이름·부서/직급·새로고침 → 메시지 기록 → 작성 영역** 순서다. 하단 탭바는 없다. 뒤로는 이전 화면으로, 이전 화면이 없으면 직원 채팅 목록으로 이동한다. 작성 내용이 있으면 나가기 확인을 제공한다.

간결한 52px 안팎 헤더, 16px 바깥 여백, 4/8/12/16px 간격, 얇은 경계, 절제된 곡률, 기존 라이트/다크 색과 선형 아이콘을 사용한다. 소개 문구·큰 장식·사진·온라인·입력 중·그룹 채팅·메시지 수정/삭제·검색·통화·고정 메뉴는 추가하지 않는다. 본문을 충분히 보여주고 보조 정보 때문에 작성 영역이 밀려나지 않게 한다.

받은 메시지와 보낸 메시지는 좌우 및 표면으로 구분한다. 메시지 본문은 줄바꿈을 보존하고 선택·복사할 수 있다. 보낸 메시지 아래에는 한국시간 월/일·24시간 시/분과 **읽음/안 읽음**을 표시한다. 받은 메시지에는 시각만 표시한다. 사람 수나 숫자 1로 읽음 상태를 표현하지 않는다. 오늘·어제·날짜 구분선은 만들지 않고 메시지별 시각을 유지한다. 이전 기록은 **이전 메시지 50개 불러오기** 행동으로 위에 추가하고 읽던 위치를 보존한다. 아래를 보고 있을 때 새 메시지를 따라가고 위의 기록을 읽고 있을 때 강제로 아래로 이동하지 않는다.

## 작성과 파일

메시지는 최대 2,000자, 파일은 한 번에 한 개다. 본문만, 파일만, 본문과 파일을 함께 보낼 수 있다. 작성 영역에는 **메시지 입력**, 글자 수, **파일 선택**, **보내기**를 제공한다. 빈 내용에서는 보내기가 비활성이다. 긴 본문은 작성란 안에서 스크롤하고 화면의 모든 높이를 차지하지 않는다. 키보드 위에 필수 작성 행동이 남아야 한다.

파일 선택 후 이름과 크기를 표시한다. 선택된 파일을 바꾸거나 입력 전체를 버릴 때 기존 작성 내용 버리기 확인 흐름을 사용한다. 전송 중에는 중복 보내기·입력 변경·새 파일 선택을 막고 진행률을 표시한다. 진행률을 모르면 **전송 중**, 값이 있으면 **전송 42%**처럼 표시한다. 파일 전송에는 취소 행동이 있다.

전송 성공은 입력·선택 파일을 비우고 실제 성공 메시지를 기록에 추가하는 모의 동작이다. 실패하면 입력을 보존한다. **전송 결과가 불명확한 상태**에서는 입력과 파일을 잠그고 **같은 전송 다시 확인**을 제공한다. 이 행동은 같은 전송을 확인하며 새 메시지로 자동 재전송하지 않는다. 작성 내용 버리기와 나가기는 확인을 받고, 결과 불명확 시 이미 보내졌을 가능성을 안내한다.

첨부 메시지는 파일명·크기·상태와 **파일 작업 열기**의 44px 이상 행동을 제공한다. 파일만 보낸 경우 자동 본문 ‘파일: 파일명’을 첨부와 중복해 크게 반복하지 않아도 된다. 파일 작업의 실제 경고와 버튼 흐름은 유지한다. 이번 시안에는 파일 작업 모의 패널과 미리보기 이동 목적지만 포함하고, 파일 미리보기 화면의 내부 디자인은 다음 작업으로 둔다.

받은 파일은 외부에 저장한 다음 **파일을 저장했습니다 · 수신 완료**를 확인하면 원본을 다시 받을 수 없음을 명확하게 안내한다. 공유 화면을 닫은 것을 실제 저장 완료로 단정하지 않는다. 불명확한 수신 완료는 **원래 수신 완료 상태 확인**, 삭제된 원본은 다운로드 불가로 표현한다. 보내기와 파일 수신 완료를 혼동하는 체크 표시를 사용하지 않는다.

## 대표 합성 자료

390×844 라이트. 상대 **김예시**, **지원팀 · 담당**. 한국시간 10. 6. 09:30~09:40에 ‘오늘 회의 자료 확인 부탁드립니다.’, ‘네, 확인하겠습니다.’, ‘검수용 자료를 첨부했습니다.’ 등 합성 메시지 6개. 받은 파일 `회의자료_검수예시.pdf` 1.2MB, 보낸 메시지 읽음과 안 읽음 각각 포함. 사진과 실명·업무 원문은 사용하지 않는다. 360×800 다크, 긴 이름·파일명·문단·이모지·영문 긴 단어, 0/1/다수, 200% 상당 크기, 1366×768도 확인한다.

## 상태와 완료 기준

| 상태 | 표현과 행동 |
| --- | --- |
| 최초·재진입·복귀·수동 확인 | 이전 이름·본문 없이 대화 확인 중, 조작 잠금. 확인 성공 뒤 내용 표시. |
| 최초 확인 실패 | 오류와 다시 불러오기. 정상 빈 대화와 구분. |
| 빈 대화 | 아직 메시지가 없습니다 + 첫 메시지 안내, 작성 영역 유지. |
| 이전 기록 확인 중/실패 | 현재 기록과 읽던 위치 유지, 이전 기록 행동에 상태 표시. |
| 주기 확인 실패 | 같은 현재 대화의 마지막 확인 내용은 남을 수 있음. 오류·재시도. |
| 읽음 처리 실패 | 메시지를 보낸 것으로 오인하지 않는 읽음 상태 오류와 다시 확인. |
| 전송 성공/일반 실패 | 성공 때만 입력 비움, 실패 입력 보존. |
| 전송 중/선택 중/취소/결과 불명확 | 명확한 상태와 실제 잠금, 같은 전송 확인, 버리기 확인. |
| 비활성 직원 | 기록을 보여주고 새 메시지를 보낼 수 없는 이유 표시. 불명확했던 원래 전송 확인은 유지. |
| 앱 비활성·계정 변경·세션 만료 | 사적 내용 즉시 제거. 늦은 응답으로 복원하지 않음. |

최소 44×44px 행동, 일반 글자 4.5:1 대비, 보이는 키보드 포커스, 한 주 제목과 의미 있는 메시지 목록, 가로 넘침·겹침 없음. 큰 글자에서도 이름·읽음·파일명·전송 재확인·버리기·닫기 행동이 남아야 한다. 특히 결과 불명확 안내가 길어져 메시지와 작성 행동을 모두 가리는 구조를 피한다. 모의 테마·전경·계정·응답·키보드 제어는 앱 화면 밖에 둔다.

**직원 대화방 v1** 페이지, 대표·주요 상태 PNG, 동작하는 모의 프로토타입, 편집용 `bajaul-chat-thread-v1-source.zip`, 검수 결과와 미확인 항목을 제공한다. 실제 iOS/Android·키보드·스크린리더·파일 저장과 모의 검증은 구분해서 기록한다.
