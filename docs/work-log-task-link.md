# 할 일 완료와 업무일지 자동 연동

직원이 할 일을 완료하면 **완료한 한국 날짜의 본인 업무일지**에 자동 기록으로 표시한다. 마감일이나 할 일 생성일을 업무일지 날짜로 사용하지 않는다. 해당 날짜에 직접 쓴 내용이 없어도 잔디 그래프, 최근 업무일지, 날짜별 상세 조회에 기록이 나타난다.

완료한 할 일은 직접 입력하는 키워드·본문과 분리한다. 업무일지에 같은 문장을 다시 입력하거나 저장할 필요가 없으며, 직접 작성한 내용을 수정하거나 삭제해도 자동 기록은 유지된다. 자동 기록만 있는 날에는 수동 삭제 버튼을 표시하지 않고 ‘추가 기록’으로 별도 내용을 작성할 수 있다.

자동 기록은 현재 완료 상태의 할 일을 조회해서 구성한다. 완료 취소 또는 할 일 삭제 시 자동 기록에서 빠지고, 다시 완료하면 새 완료 날짜에 반영된다. 기존 수동 업무일지의 내용 및 수정 시각을 자동 기록 때문에 덮어쓰지 않는다. 별도 업무일지 행을 복제하지 않아 중복 기록이나 완료 취소 후 남는 복사본이 생기지 않는다.

## 확인 범위

- 날짜 경계는 한국 시간 00:00 이상, 다음 날 00:00 미만으로 조회한다.
- 본인에게 배정되고 본인 계정으로 완료한 할 일만 반영한다. 다른 직원의 할 일이나 기록을 페이지 데이터에 포함하지 않는다.
- 자동 기록이 있어도 신규 수동 기록의 `expectedUpdatedAt` 값은 빈 문자열이다. 기존 수동 기록은 그 수동 기록의 수정 시각을 사용해 충돌을 확인한다.
- 할 일 완료·취소·삭제 및 배정 변경 시 업무일지 경로도 다시 검증한다. 상세 모달은 열릴 때 날짜별 API에서 현재 기록을 다시 조회한다.

## 브라우저 검수 방법

실제 `WorkLogBoard`, `StaffTaskChecklist`, `AppModal`, 전역 CSS를 묶은 격리 브라우저 화면에서 확인한다. Next 라우터와 서버 액션의 경계만 모의 구현하고, 직원·할 일·업무일지는 합성 데이터를 사용한다. 운영 환경 변수, Prisma 또는 운영 DB를 불러오지 않으며 실제 직원의 할 일 완료/삭제 요청을 보내지 않는다. 이 브라우저 검수는 화면과 액션 연결을 확인하며 실제 서버 권한·날짜 조회는 단위 테스트로 별도 확인한다.

실행 명령: `npx.cmd playwright test --config playwright.work-log.config.ts`

검수 경로: 격리 fixture의 `/tasks`, `/work-schedule/work-log`, 날짜 선택, 잔디에서 연 업무일지 상세 모달.

각 뷰포트에서 라이트·다크 화면을 촬영해 확인했다. 새 자동 기록 배지는 다크 모드 본문색을 사용하도록 수정해 작은 글자의 대비를 확보했다. 실제 항목이 많거나 제목이 길어 발생하는 세로 스크롤은 허용하며, 잔디 그래프의 좌우 스크롤은 기존의 의도된 달력 탐색이다.

추가 확인 사항:

- 실제 할 일 체크박스를 완료한 뒤 완료 날짜의 잔디·최근 기록·자동 패널에 표시된다. 기한이 지난 할 일도 마감일에 잘못 표시되지 않는다.
- 자동 기록은 편집할 체크박스나 본문으로 복사되지 않는다. 기존 수동 본문과 충돌 확인 값은 보존된다.
- 자동 기록만 있는 상세에서 수동 내용을 새로 저장한 후 그 수동 내용만 삭제해도 자동 항목과 잔디가 유지된다.
- 저장 중 버튼 비활성화, 실패 후 입력 보존 및 오류 포커스 이동을 확인했다.
- 날짜 변경과 할 일 이력 링크 이동 시 미저장 내용의 취소/보존을 확인했다. 상세 모달 안의 이력 링크에도 같은 보호가 적용된다.
- 모달의 최초 포커스, Tab/Shift+Tab 순환, Escape 닫기, 잔디 실행 버튼으로 포커스 복귀 및 행동 버튼 44×44px 이상을 확인했다.
- 최근 목록에 없는 자동 기록의 상세 API 로드, 로드 실패와 재시도를 확인했다.
