# 직원 할 일

회의에서 정리한 업무를 관리자에서 직원별로 등록하고, 직원이 완료 여부를 직접 기록한다.

## 사용 방법

- 관리 → **직원 할 일** (`/admin/tasks`)에서 **할 일 등록**을 선택한다.
- 할 일과 담당 직원을 입력한다. 기한, 회의명, 상세 내용은 선택 사항이다.
- 직원의 메인페이지 **내 할 일**에 미완료 업무가 기한순으로 표시된다.
- 직원은 메인페이지와 **내 할 일**에서 **할 일 추가**로 본인 업무를 등록한다. 담당자는 로그인한 본인으로 고정된다.
- 본인에게 배정된 업무는 **삭제** 확인 후 목록에서 제외할 수 있다. 관리자에게 배정받은 업무도 포함한다.
- **삭제됨**에서 삭제된 업무를 확인하고, 각 업무의 **이력**에서 처리자·시각·변경 내용을 확인한다. 삭제된 업무는 수정하거나 완료 처리할 수 없다.
- 체크하면 완료 시각이 저장된다. **최근 완료**를 펼쳐 완료를 취소할 수 있다.
- **전체 보기** (`/tasks`)에서 본인 업무를 상태별로 조회한다. 목록은 20건씩 표시된다.
- 관리자는 직원별 미완료·완료·기한 초과 건수를 확인하고, 목록에서 업무를 수정한다.
- 다른 직원이 변경한 최신 상태는 관리자 화면의 **새로고침**으로 확인한다.

회의 내용에서 담당자나 기한을 확정한 뒤 등록한다. 이 기능에는 회의 원문 자동 분석을 포함하지 않는다.

## 권한과 저장

- 일반 직원의 목록·건수 조회와 완료 처리는 로그인한 본인에게 한정된다.
- 관리자는 다른 직원에게 업무를 등록·수정하고 전체 현황 및 삭제된 업무 이력을 조회한다. 다른 직원의 완료 처리나 삭제는 할 수 없다.
- 완료한 업무의 담당자는 변경하지 않는다. 필요한 경우 새 업무를 등록한다.
- 등록 요청 ID로 중복 등록을 방지하고, 버전 검사로 다른 창의 변경 내용을 덮어쓰지 않는다.
- 날짜는 한국 날짜 기준이며, 마감일 다음 날부터 기한 초과로 표시한다.
- 등록·수정·완료·완료 취소·삭제는 업무 변경과 같은 트랜잭션에서 감사 이력을 기록한다. 이력 저장에 실패하면 업무 변경도 취소된다.
- 삭제는 `deletedAt`을 저장하는 방식이며 원본과 완료 기록을 보존한다. 일반 목록과 진행 건수에서 제외하고 **삭제됨**에서 별도로 조회한다.
- 새 이력은 변경 전후 업무 내용도 보존한다. 이전에 등록된 이력은 당시 저장된 메시지를 표시하며, 없던 변경 전후 내용을 소급 생성하지 않는다. 본인 업무의 현재 담당자와 관리자만 이력에 접근한다.
- `StaffTask` 테이블은 RLS를 활성화하며, 권한을 검사하는 서버를 통해 접근한다.

## 운영 반영

앱 배포 전에 `20260907120000_add_staff_tasks`와 `20260907160000_add_staff_task_soft_delete` 마이그레이션을 적용해야 한다.
후자는 삭제 시각과 인덱스를 추가하며 기존 업무와 감사 이력을 보존한다.

```sh
npm run db:deploy
npm run db:generate
npm run build
```

Windows PowerShell에서 실행 정책으로 `npm`이 차단되면 `npm.cmd`를 사용한다.
마이그레이션은 프로젝트에 설정된 DB를 대상으로 하므로 실행 전 대상과 대기 중인 마이그레이션을 확인한다.
