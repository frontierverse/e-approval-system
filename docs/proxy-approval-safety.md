# 대리결재 처리 기준

## 권한과 기록

- 별도의 위임자·위임 기간 관리 기능이 없는 현재 시스템에서는 **기안자가 아닌 관리자**만 대리결재할 수 있다.
- 기안자는 관리자여도 자기 문서를 대리승인할 수 없다. 일반 결재선 참여자라는 이유만으로 다른 결재자를 대신할 수 없다.
- 본인 현재 단계만 처리할 때는 일반 승인을 사용한다.
- 대리승인·대리반려 사유는 서버에서 2~1,000자로 검증한다. 처리자, 대상 결재자, 시각, 사유를 결재 단계와 감사 이력에 기록한다.
- 화면과 서버는 동일한 권한 함수를 사용한다. 처리 중 버튼을 비활성화하고, 검증 실패 후 입력한 사유를 유지한다.

## PDF

- 원 결재선의 이름은 결재란에 유지한다. 대리승인 도장은 실제 처리자의 등록 이미지 또는 실제 처리자 이름으로 생성하며 `대리 · 처리자 이름`을 표시한다.
- 과거 기록에서 대리 처리자를 확인할 수 없으면 원 결재자의 도장을 대신 사용하지 않고 확인 필요 상태를 표시한다.
- 회수·반려 시 감사 이력으로 식별한 자동 결재본만 `[효력 취소]` 이력으로 전환한다. 같은 이름의 사용자 첨부파일을 자동 결재본으로 간주하지 않는다.
- 취소된 PDF의 저장 원본 바이트는 보존한다. 미리보기·다운로드 응답에는 모든 페이지에 효력 취소 표시를 추가한다.
- 새 결재본 생성은 취소된 사본을 덮어쓰지 않는다. 원본문서 갱신 과정에서도 해당 증거 파일과 원본의 관계를 보존한다.

## 반려와 동시 처리

- 문서를 먼저 잠근 뒤 상태를 읽는다. 일반 승인·반려, 대리승인·반려, 회수, 재상신과 초안 수정은 같은 문서 잠금 순서를 따른다.
- 먼저 완료된 처리의 상태를 후속 요청이 다시 읽어 검증하므로, 승인 중복·회수 상태 덮어쓰기를 방지한다.
- 완료된 대리결재 반려는 문서 반려, 연차 복원, PDF 효력 취소, 미처리 결재 알림 제거를 하나의 트랜잭션으로 처리한다.
- 연차는 현재 계산 규칙으로 다시 계산하지 않고, 원래 기록한 차감량의 반대 금액을 별도 복원 이력으로 추가한다. 원래 차감 이력은 수정하지 않는다.
- 기존 스키마의 문서당 원장 항목 제한을 유지한다. 복원 항목은 `approval-reversal:<원래 원장 ID>`를 고유 키로 사용해 중복 복원을 방지한다.

## 검증

- 권한 우회, 사유 검증, 승인 중복, 정상 승인과 대리승인의 충돌, 회수와 승인의 선후관계, 반려 중복, 연차 복원, 부분 실패 롤백을 회귀 테스트한다.
- GitHub CI의 일회용 PostgreSQL에서 실제 트랜잭션을 이용한 동시 승인·회수·반려 테스트를 실행한다. 해당 테스트는 운영 DB에 연결할 수 없도록 접속 문자열을 제한한다.
- PDF에서 실제 대리 처리자·취소 표시를 텍스트로 확인하고 A4 렌더링을 검수한다.
- 결재 진행 컴포넌트의 로컬 검수 경로는 `/api/health/proxy-review`이며 검수용 페이지는 배포에 포함하지 않는다.
- 1366×768, 390×844, 320×800 및 모바일 다크 모드에서 진행 상태·결재자·사유 입력·처리 버튼을 확인했다. 가로 넘침이 없으며, 처리 중 제출 차단과 오류 후 사유 보존을 확인했다.

명시적 위임 기능을 도입하려면 지정 주체, 대리인 범위, 유효 기간, 취소 절차를 별도로 정의해야 한다. 현재 관리자 제한을 일반 직원에게 확대하는 것으로 대체하지 않는다.
