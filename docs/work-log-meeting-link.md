# 회의록 파일과 업무일지 연동

업무일지의 회의 날짜에 열람 가능한 회의록 파일을 자동 연결한다. 회의록과 첨부파일을 별도로 복제하지 않고 기존 문서의 파일을 사용하며, 직접 작성한 업무 내용과 할 일 완료 기록은 각각 유지한다.

자동 연결 대상은 **첨부파일이 있고 결재가 완료된(`APPROVED`) 회의록 중 본인이 기안자 또는 결재자인 문서**다. 회의록 본문에 기록된 회의 날짜에 연결하며, 문서 작성일·제출일·결재 완료일을 회의 날짜 대신 사용하지 않는다. 진행 중·반려·회수·삭제된 문서나 다른 직원의 관련 없는 회의록은 자동 연결 대상에서 제외한다.

회의록 파일만 있는 날짜도 잔디, 최근 업무일지와 상세 조회에서 확인할 수 있다. 파일 미리보기와 다운로드에는 원본 문서의 권한 확인을 그대로 적용한다. 업무일지에서 파일을 미리 보거나 다운로드해도 회의록의 원본 파일은 삭제하지 않는다.

## 브라우저 검수 방법

실제 `WorkLogBoard`, 회의록 파일 패널, 미리보기 및 `AppModal`을 기존 업무일지 격리 fixture에서 실행한다. Next 탐색과 서버 액션의 경계만 모의 구현하며, 직원·회의록 데이터와 PDF·이미지는 모두 합성 데이터다. 운영 환경 변수와 DB를 불러오지 않으며 직원 문서 또는 실제 첨부파일에 접근하지 않는다.

PDF는 테스트가 생성한 두 페이지 문서를 실제 PDF.js로 렌더링한다. PDF.js의 공개 워커·지원 파일은 허용한 경로만 제공한다. 파일 다운로드와 미리보기 요청은 브라우저 테스트에서 가로채 합성 바이너리 또는 권한 오류로 응답한다.

실행 명령: `npx.cmd playwright test --config playwright.work-log-meeting.config.ts`

검수 경로: 격리 fixture의 `/work-schedule/work-log?date=2026-09-07`, 날짜별 잔디에서 연 업무일지 상세, 그 안에서 연 PDF·이미지 미리보기.

확인할 동작:

- 회의록 파일만 있는 날짜의 자동 패널·최근 기록·잔디·상세 조회.
- 수동 내용과 완료한 할 일이 있는 업무일지에 회의록을 연결해도 입력 내용과 수정 확인 시각 보존.
- 상세 모달 안의 PDF 미리보기, 페이지 전환, 미리보기 닫기 및 바깥 모달 유지, 원래 실행 위치로 포커스 복귀.
- 이미지 미리보기와 반복 다운로드 후 원본 연결 유지.
- 권한 오류 후 업무일지 화면 유지, 오류 표시와 재시도.
- 1366×768, 390×844, 320×800, 683×384의 라이트·다크 화면에서 긴 파일명, 44px 행동 버튼, 가로 넘침과 모달 탐색 확인.

## 검수 결과

2026-09-08 기준 신규 브라우저 테스트 13개가 통과했다. 공통 6개 업무 흐름을 데스크톱·모바일에서 각각 실행하고, 별도의 반응형 매트릭스 1개를 확인했다. 모바일에서 동일 매트릭스를 반복하는 1개는 의도적으로 제외한다. 기존 할 일 자동 기록 브라우저 회귀 테스트 13개와 fixture/spec/config의 ESLint도 통과했다.

| 검수 뷰포트 | 첫 화면에서 확인한 내용 | 넘침 및 동작 |
| --- | --- | --- |
| 1366×768 | 회의록 파일 수, 회의 날짜·제목, 파일명·크기·서명본 표시, 미리보기·다운로드 | 파일 목록이 잔디 위에 표시되고 페이지 가로 넘침 없음 |
| 390×844 | 파일 수와 실제 첨부 목록, 각 파일의 미리보기·다운로드 | 두 행동을 같은 행에 유지. 페이지 가로 넘침 없음 |
| 320×800 | 긴 회의록 파일명이 줄바꿈되고 미리보기 제목·페이지·닫기 유지 | 모든 미리보기 행동 버튼이 44×44px 이상. 가로 넘침 없음 |
| 683×384 (200% 확대에 해당하는 CSS 뷰포트) | 회의록 제목과 자동 첨부 목록의 시작, 미리보기의 제목·닫기·페이지 이동 | 문서는 본문 영역에서 세로로 탐색하고 핵심 행동은 유지. 가로 넘침 없음 |

위 네 크기에서 라이트·다크 스크린샷을 직접 확인했다. PDF는 실제 두 페이지 합성 문서를 렌더링하고 페이지 이동을 검증했다. 이미지의 실제 로드 크기도 확인했다. 업무일지 상세에서 미리보기를 열고 `Escape`로 닫으면 상세 모달이 유지되고, 다시 닫으면 잔디 버튼으로 포커스가 돌아온다.

직접 작성 중인 내용이 있을 때 회의록 원문 링크를 누르면 이동 확인을 제공한다. 페이지와 상세 모달 양쪽에서 취소했을 때 현재 화면과 미저장 본문이 그대로 보존되는 시나리오를 추가하고 데스크톱·모바일 2개 모두 통과했다.

중첩 미리보기를 연 채 SPA 경로를 변경하면 두 모달이 동시에 사라진 뒤에도 `body.style.overflow`가 `hidden`으로 남는 문제를 수정 전에 실제 브라우저에서 재현했다. 공통 모달이 열린 개수를 기준으로 스크롤 잠금을 관리하도록 수정한 뒤, 데스크톱·모바일에서 동시 종료와 일반 순서 종료를 재검증해 4개가 통과했다. 원래 값이 빈 문자열 또는 `auto`인 경우 모두 복구되며, 안쪽 미리보기만 닫았을 때는 바깥 업무일지 모달의 잠금이 유지된다.

미리보기와 반복 다운로드에서 서버 요청은 `GET`만 발생한다. 다운로드 뒤에도 파일명이 유지되고 재다운로드할 수 있다. 권한이 없어 미리보기·다운로드가 실패하면 현재 업무일지를 유지하고 오류 및 재시도 동작을 제공한다. 이 테스트는 합성 응답에 대한 UI 처리를 확인하며, 실제 서버의 권한 범위·회수·삭제 및 회의 날짜 경계는 별도 단위 테스트에서 확인한다.
