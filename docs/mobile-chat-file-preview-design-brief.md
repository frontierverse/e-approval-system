# 바자울 모바일 채팅 파일 미리보기 v1 디자인 브리프

2026-10-06. 기존 Claude 작업 ‘바자울 전자결재 앱 디자인’에 **채팅 파일 미리보기 v1**을 새 페이지로 추가한다. 현재 문서를 다시 읽고 기존 페이지·보드·파일·메모를 보존한다. 직원 대화방 v1과 직원 채팅 목록 v1의 시각 언어를 이어간다. 디자인과 프로토타입에는 합성 자료만 사용하고, 실제 앱 반영·검증·배포는 Codex가 담당한다.

## 목적과 범위

대화에서 받은 또는 보낸 PDF·이미지를 읽고 대화로 돌아오는 화면이다. **미리보기는 수신 완료가 아니며 서버 원본을 삭제하지 않는다.** 저장·공유·수신 완료는 기존 대화의 파일 작업 패널에서 한다. 미리보기 화면에는 저장·공유·삭제·수신 완료·편집·주석·인쇄·검색·외부 URL 열기 행동을 새로 넣지 않는다.

지원 파일은 최대 4MiB의 PDF, PNG, JPEG, GIF, WebP다. 파일명만 맞으면 표시하는 것이 아니라 실제 형식과 크기를 확인한 뒤 보여준다. ZIP·HWP·DOCX 등은 기존 파일 작업에서 저장하고, 미리보기를 지원한다고 꾸미지 않는다. 새 기능·서버·라이브러리를 제안하는 작업이 아니다.

## 화면 구성

**뒤로 → 파일 미리보기 제목 → 확인된 파일명·형식·크기 → 파일 내용** 순서다. 하단 탭바는 없다. 대화방과 같은 간결한 52px 안팎 헤더, 16px 바깥 여백, 4/8/12/16px 간격, 얇은 경계, 기존 라이트·다크 토큰과 선형 아이콘을 사용한다. 파일명이 길어도 옆 버튼과 겹치지 않게 줄바꿈하고 전체 접근 이름을 보존한다. 상단 소개·큰 카드·불필요한 파일 아이콘·가짜 기기 프레임 때문에 내용을 축소하지 않는다.

PDF는 설치된 앱의 기존 PDF 뷰어를 사용한다. 세로 페이지 스크롤과 기본 확대 동작을 유지하며 별도의 페이지 이동·확대 버튼·페이지 수를 꾸며 넣지 않는다. 합성 PDF 본문을 보여주는 디자인 보드는 만들 수 있지만, 앱이 실제 페이지 수를 제공하지 않는 상태에서 임의의 ‘1/8’ 등을 사용자 UI에 넣지 않는다. 큰 화면에서도 문서 읽기 영역의 높이를 충분히 남긴다.

이미지는 기존 비율을 보존하여 전체 내용이 보이게 한다. 가로·세로·매우 긴 이미지에서 잘라서 채우지 않는다. 확대 제스처나 회전 버튼을 임의로 추가하지 않는다. 문서·이미지 내용은 라이트·다크 모두 원래 색을 유지하고 주변 표면만 테마를 따른다.

짧은 안내 **‘미리보기만으로 수신 완료하거나 원본을 삭제하지 않습니다.’**를 한 번만 제공한다. 읽기 영역을 가리는 큰 경고나 반복 설명으로 만들지 않는다. 뒤로는 이전 화면으로, 이전 화면이 없으면 해당 대화로 돌아간다. 유효한 대화 식별자가 없으면 직원 채팅 목록으로 이동한다.

## 조회·표시 상태

| 상태 | 표현과 행동 |
| --- | --- |
| 최초 진입·다시 확인·앱 복귀 | 일반 제목과 ‘미리보기 확인 중’. 이전 파일명·크기·본문·이미지·오류를 모두 제거한다. 조회 성공 뒤 확인된 파일만 표시한다. |
| PDF 정상 | 확인된 이름·PDF·크기, 넓은 문서 뷰어. 내장 스크롤·확대 동작 유지. |
| 이미지 정상 | 확인된 이름·형식·크기, 비율 보존한 전체 이미지. |
| 연결·조회 실패 | 내용을 비우고 짧은 오류 + ‘미리보기 다시 확인’ + 뒤로. 정상 빈 파일처럼 표현하지 않는다. |
| 이미지 표시 실패 | 기존 내용을 제거하고 오류·재확인. 실패한 이미지나 이전 파일명을 남기지 않는다. |
| PDF 뷰어 표시 실패 | 파일 내부를 읽지 못했다는 안내와 기존 다시 시도 행동. 실제 네이티브 뷰어와 모의 상태를 구분한다. |
| 대화에서 다시 선택 필요 | 주소 직접 진입·새로고침 등으로 파일 선택 정보가 없는 경우. ‘대화에서 파일을 다시 선택해 미리보기를 여세요.’ + 뒤로. 사적 이름을 추측하지 않는다. |
| 원본 삭제·삭제 중 | ‘원본이 삭제되어 미리볼 수 없습니다.’ 등 실제 응답에 맞는 설명. 삭제 상태는 중립적인 표면으로 표시하고 정상 내용·저장 가능 행동을 제공하지 않는다. |
| 지원하지 않는 형식·크기·실제 형식 불일치 | 안전한 미리보기를 제공할 수 없다는 짧은 안내. 대화의 파일 작업으로 돌아가도록 설명한다. 미리보기에서 다운로드를 실행하지 않는다. |
| 권한 없음 | 접근할 수 없다는 안내, 파일명·크기·내용 없이 뒤로. |
| 앱 비활성·화면 이탈·계정 변경 | 파일명·크기·오류·내용을 즉시 제거하고 늦은 응답을 무시한다. 복귀 시 다시 확인한다. |
| 로그인 만료 | 파일 정보를 제거하고 기존 로그인 흐름으로 이동하는 모의 동작. |
| 웹 PDF | ‘PDF 미리보기는 설치한 모바일 앱에서 제공됩니다.’ 기존 안내. 웹에서 실제 PDF가 렌더링된 것처럼 주장하거나 새 외부 뷰어를 붙이지 않는다. |

보이는 비활성과 실제 클릭 차단이 일치해야 한다. 재확인 연타는 요청 한 번만 시작한다. 화면을 나간 후 늦게 도착한 파일이 다시 표시되지 않아야 한다. 미리보기·재확인·뒤로·앱 복귀는 수신 완료·원본 삭제·메시지 전송·읽음 요청을 발생시키지 않는다.

## 합성 자료와 검수

대표 390×844 라이트 PDF: `회의자료_검수예시.pdf`, 1.2MB. 본문은 ‘검수용 회의 자료’, ‘실제 업무 문서가 아닙니다.’, 안건·예시 일정 같은 합성 텍스트만 사용한다. 실명·직원 기록·개인정보·운영 문서·고객 자료를 사용하지 않는다. 이미지 보드는 실제 제공된 비민감 이미지 자산이 있을 때 사용하며, 없으면 이미지 슬롯의 표시 비율과 상태를 명시하고 이미지를 실제로 확보했다고 주장하지 않는다.

390×844 라이트/다크, 360×800, 200% 상당 글자, 긴 한글·영문 파일명, 가로·세로·긴 이미지, 1366×768을 확인한다. 미리보기 화면에는 목록 40% 규칙을 기계적으로 적용하지 않고 내용 읽기를 우선한다. 적어도 44×44px 행동, 한 주 제목, 보이는 키보드 포커스, 일반 글자 4.5:1·중요 경계 3:1 대비, 가로 넘침·겹침 없음이 필요하다. 큰 글자에서도 뒤로·오류 재확인·내용 영역이 남아야 한다. 개인정보는 CSS로만 가리지 말고 DOM에서도 제거한다.

모의 응답·파일 종류·테마·크기·글자·전경·계정 제어는 앱 밖 검토 패널에 둔다. 대표 PDF·이미지·상태 PNG, 작동하는 합성 프로토타입, 편집 소스 `bajaul-chat-file-preview-v1-source.zip`, 검수 결과와 미확인 항목을 제공한다. 실제 iOS/Android 뷰어·스크린리더·앱 생명주기와 합성 모의 검증 결과를 구분한다. 캔버스에 추가하기 직전 원본을 다시 읽고 다른 화면을 덮어쓰지 않는다.
