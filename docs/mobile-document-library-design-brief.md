# Claude Design 전달: 바자울 모바일 문서함

기준일: **2026-10-05 (한국시간)**. 현재 운영 main `8cc2353`의 문서함 기능을 기준으로 한다. 기존 Claude Design 작업 **바자울 전자결재 앱 디자인**의 새 페이지 **문서함 v1**에서 모바일 문서함의 시안과 모의 프로토타입을 만든다. 완성된 **홈 v2**의 시각 체계를 이어간다.

이번 범위는 문서함 목록과 목록 안의 검색·필터·기간 선택·페이지 이동·상태 변형이다. 홈 v2를 수정하지 않고, 로그인·기안 작성·문서 상세·작성 복구 화면을 새로 설계하지 않는다. 외부 운영 API를 조회하거나 운영 앱 코드·DB·배포를 변경하지 않는다. 첨부한 모의 데이터와 참고 화면만 사용한다.

## 자료 우선순위와 목표

1. 이 브리프: 실제 기능·권한·행동·이번 범위.
2. UI/UX 가이드라인: 밀도·접근성·상태·검수의 필수 기준.
3. 최신 문서함 계약 요약: 실제 목록 필드와 조회 조건.
4. 홈 v2의 기존 캔버스와 첨부한 적용 화면: 색상·타이포·간격·하단 탐색의 기준.
5. 기존 문서함 캡처: 기능 구조만 참고. 이전 색상·카드·텍스트 탭바를 그대로 재현하지 않는다.

사용자는 원하는 문서를 빠르게 찾고, 진행·완료·기안 상태를 구분하고, 열람 또는 계속 작성으로 이동해야 한다. 장식·큰 요약 카드보다 문서 제목과 상태를 먼저 읽게 한다. 새 기능을 발명하기보다 기존 기능을 빠르고 일관되게 사용할 수 있도록 설계한다.

## 문서함 종류와 권한

| 분류 | 표시 범위 | 상태 필터 | 기간 기준 | 행을 누르면 |
| --- | --- | --- | --- | --- |
| 제출 문서 | 본인이 상신한 문서 | 전체 / 진행 중 / 승인 / 반려 | 상신일 | 문서 상세 열람 |
| 완료 문서 | 본인이 기안했거나 결재선에 포함된 승인·반려 문서 | 전체 / 승인 / 반려 | 완료일 | 문서 상세 열람 |
| 기안함 | 본인의 임시저장·회수 문서 | 전체 / 임시저장 / 회수 | 최종 수정일 | 기존 기안을 계속 작성·수정 |

일반 직원과 시설장은 같은 문서함 구조를 사용한다. 관리자 역할만으로 목록에서 다른 직원의 문서 전체가 보이지 않는다. 본인·결재선의 서버 권한을 따른다. 시설장에게만 하단 받은결재 탭을 표시한다. ‘받은결재’를 문서함의 네 번째 분류로 추가하지 않는다.

## 화면의 실제 기능

- 짧은 **문서함** 제목, 현재 목록의 총수 또는 검색 결과 수, **새 기안**을 compact 헤더로 구성한다. API는 현재 조건의 총수만 주므로 세 분류별 총수나 전체 상태별 KPI 숫자를 만들지 않는다.
- 분류는 **제출 문서 / 완료 문서 / 기안함** 세 개다. 기본은 제출 문서·전체·최신순·1페이지다.
- 검색 대상은 제목·문서번호·분류·기안자다. 검색어 입력 중에는 목록을 임의 변경하지 않고 검색 버튼 또는 키보드 검색으로 적용한다. 최대 100자다.
- 분류에 맞는 상태 필터를 제공한다. ‘진행 중’은 상신과 결재 중을 함께 포함한다.
- 기간은 기본적으로 접어 두고, 버튼으로 시작일·종료일과 적용/지우기를 연다. 선택 중인 값과 적용된 조건을 구분한다. 한쪽 날짜만 입력해도 조회할 수 있다. 날짜는 한국 시간 기준이다.
- 시작일이 종료일보다 늦거나 실제로 없는 날짜면 명확한 오류와 수정 위치를 보여 주고 입력을 보존한다. 오류 때문에 임의로 초기화하거나 조회를 실행하지 않는다.
- 최신순 / 오래된순 정렬을 전환한다. 필요하면 날짜 선택 UI를 모바일에 맞게 개선하되 실제로 없는 정렬 기준이나 기간 프리셋의 새 업무 의미를 만들지 않는다.
- 검색·상태·기간이 적용되면 현재 조건을 알아볼 수 있고 **초기화**로 기본 검색 상태에 돌아갈 수 있어야 한다.
- 분류 변경: 검색어와 정렬은 유지하고 상태·기간·페이지는 초기화한다. 검색·상태·기간·정렬 변경 시 페이지는 1로 돌아간다.
- 페이지 크기는 **20건**이다. 전체 페이지가 2 이상일 때 이전 / 현재 페이지·전체 페이지 / 다음을 제공한다. 처음·마지막 및 조회 중인 페이지 이동은 비활성 상태를 명확히 표시한다. 무한 스크롤로 바꾸지 않는다.
- 당겨서 새로고침, 상세에서 돌아온 뒤 현재 조건·페이지 유지와 목록 갱신을 표현한다. 오래된 요청 응답이 새 조건의 목록을 덮으면 안 된다.
- **기안함에서만 ‘작성 복구’ 진입점**을 유지한다. 별도 보관된 미확정 작성 입력을 확인하는 기존 기능이다. 일반 임시저장 문서와 같은 것처럼 합치지 않는다. 이번에는 목적을 알려 주는 모의 안내로만 연결한다.

## 문서 행에 사용할 데이터

실제 필드: id, title, documentNo, category, status, drafterName, createdAt, updatedAt, submittedAt, completedAt, attachmentCount, currentApproverName.

상태 표현은 **상신 / 결재 중 / 승인 / 반려 / 임시저장 / 회수**를 사용한다. 상신은 결재 요청이 올라간 상태이며 ‘진행 중’ 필터에 포함된다. 배지의 문구는 홈 v2와 일관되게 다듬을 수 있지만 상태의 업무 의미를 바꾸지 않는다.

제목을 가장 쉽게 읽게 하고, 상태·문서번호 또는 분류·기준 날짜를 비교하게 한다. 완료 목록에는 기안자, 진행 문서에는 현재 결재자가 있으면 표시한다. 첨부 수는 실제 필드라 사용할 수 있다. 문서번호가 없는 임시저장 문서는 분류로 보완한다. 문서번호·문서 제목으로 검색되는 결과임을 행에서 확인할 수 있게 한다. 제목은 긴 한글 두 줄에서도 주요 상태를 보존한다.

금액·긴급/오늘 마감·읽음 여부·즐겨찾기·결재 단계별 진행률·반려 의견·본문·첨부 파일명은 이 목록 API에 없다. 실제 제공되는 목록 정보처럼 추가하지 않는다. 바로 승인·반려·삭제·회수·재상신, 다중 선택이나 스와이프 업무 처리를 목록에 넣지 않는다. 문서 상태를 바꾸는 작업은 기존 상세/작성 흐름을 거친다.

## 홈 v2와의 시각 일관성

네이티브 iOS·Android 앱이며 가로폭에 맞춘 웹 랜딩 페이지가 아니다. 기본 390×844, 소형 360×800을 사용한다. 홈 v2의 선형 아이콘, 얇은 경계, 절제된 파란 강조, 흰색/다크 표면, compact 헤더와 하단 아이콘 탭을 이어간다. 기존 큰 카드 반복을 더 간결한 문서 행으로 정리한다.

배경·장식 경계와 입력 컨트롤의 구분을 다르게 취급한다. 읽기와 입력에 필요한 경계·포커스는 충분한 대비를 확보한다. 간격은 4·8·12·16·24px 체계, 터치 영역은 44×44px 이상이다. 헤더·분류·검색·필터를 compact하게 묶고 기본 접힘 상태에서 첫 실제 문서 행을 스크롤 영역 상단 40% 안에서 시작하게 한다. 기간 입력 전체를 항상 펼쳐 목록을 밀지 않는다. 큰 숫자 하나를 큰 카드로 강조하지 않는다.

하단 순서는 홈 → (시설장만 받은결재) → **문서함 선택** → 알림 → 내 정보다. 새 기안은 독립 탭이 아니다. 각 아이콘은 접근 이름·선택 상태를 제공하고 실제 문서를 덮지 않도록 Safe Area를 고려한다. 알림은 별도 기능의 실제 읽지 않은 건수를 사용하는 기존 배지이고 문서함 API의 총수와 섞지 않는다. 프로토타입에서 값이 필요하면 ‘검수용 알림 3건’으로 명시한다.

## 모의 데이터와 상태

가상 사용자 김예시(직원), 이예시(시설장), 박예시(다른 시설장)만 사용한다. 이름·문서·번호·날짜·첨부 수는 전부 모의 값이다. 실제 직원·청소년·의료·인사 정보와 운영 데이터는 조회하지 않는다.

제출 목록은 총 23건·20건씩 2페이지로 만든다. 첫 행은 `프로그램 운영비 지출결의`, `EA-2026-0147`, 상신, 현재 결재자 이예시, 모의 첨부 2개로 한다. 이어 `10월 공용 사무용품 구매 요청`(결재 중), `직원 연차휴가 신청`(승인), `주간 업무회의 회의록`(반려), `2026년 4분기 운영 일정 및 공용 물품 구매 계획에 관한 일반 기안서`처럼 긴 제목을 섞는다. 승인·반려에는 현재 결재자를 표시하지 않는다. 임시저장·회수의 번호가 없는 경우도 포함한다. 반려 사유나 금액을 목록에 추가하지 않는다.

검색·상태·기간을 적용하면 실제 모의 배열을 필터하고 결과 총수·페이지를 맞춘다. 결과 0건과 원래 문서가 0건인 상태를 구분한다. 새 분류/검색 조건을 조회할 때는 이전 조건의 문서를 보여 주지 않는다. 같은 조건 새로고침에 실패했을 때만 기존 문서를 남기고 재시도를 제공한다.

## 산출물과 검수

- 새 캔버스 페이지 **문서함 v1**. 메인 390×844 제출 문서·전체·일반 직원·라이트.
- 같은 화면의 완료 문서, 기안함+작성 복구, 검색/상태 적용, 기간 입력+유효성 오류, 2페이지, 원래 0건, 검색 결과 0건, 로딩, 초기 오류/재시도, 기존 데이터 새로고침 실패를 확인 가능하게 한다.
- 360×800 긴 제목·큰 총수, 390×844 다크, 시설장 하단 탐색 변형, 200% 상당 또는 큰 글자 확인을 포함한다. 각 조합마다 중복 페이지를 만들 필요는 없고 검토용 컨트롤로 전환해도 된다.
- 검색·분류·상태·기간 적용/취소/초기화·정렬·페이지 이동·오류 재시도는 모의 데이터로 동작하게 한다. 새 기안·문서 열람/계속 작성·작성 복구·다른 탭은 목적을 분명하게 알려 주는 모의 피드백으로 연결하며 후속 화면을 만들지 않는다.
- 검토용 역할·테마·상태 컨트롤은 앱 화면 바깥에 둔다. 직원이 역할이나 데이터 상태를 바꿀 수 있는 실제 앱 기능처럼 노출하지 않는다.
- 직접 렌더한 화면의 뷰포트·첫 목록 위치·보이는 행 수·가로 넘침·터치/포커스/대비·필터 동작을 보고한다. 키보드가 열렸을 때 검색/기간 입력과 실행 버튼이 가려지지 않게 한다. 날짜 선택을 모달/시트로 만들면 포커스 진입·취소·복귀를 확인한다.
- 시안 밖의 후속 아이디어와 실제 구현·OS 검증이 필요한 항목은 구분한다. 검수하지 않은 것을 완료라고 주장하지 않는다. 편집 가능한 소스와 검토용 캡처를 함께 제공한다.
