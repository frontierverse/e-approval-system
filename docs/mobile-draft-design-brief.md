# Claude Design 전달: 바자울 모바일 기안 작성 v1

기준일 **2026-10-05 한국시간**, 실제 운영 main **7bd6cfe**. 기존 Claude 작업 **바자울 전자결재 앱 디자인**에 새 페이지 **기안 작성 v1**을 만든다. 홈 v2, 문서함 v1, 문서 상세 v1의 적용된 시각 체계를 이어간다. 이번 단계는 디자인·검토용 모의 프로토타입이며 운영 API 호출, 실제 업무 자료 조회, 앱 코드 수정·배포는 하지 않는다.

## 앱 구현 검수 상태

Claude의 **기안 작성 v1** 완성본을 기존 Expo 앱의 새 기안·DRAFT/RECALLED 수정 화면에 적용했다. 위 디자인 전달 범위와 모의 자료는 원본 요청 기록이다. 현재 변경은 검수한 PR 후보이며 운영 병합·직원 앱 OTA 배포 기록은 아니다. 구현 비교·동작·자동 검사·실기기 확인 한계는 저장소 루트 `design-qa.md`, 원본·비교 캡처는 `docs/design/mobile-draft-v1/`에 기록한다.

## 반드시 갱신할 최신 사실

모바일 임시저장 삭제는 PR #25로 구현되어 서버와 Android/iOS production OTA에 배포되었다. 본인의 서버 저장 **DRAFT**만 삭제할 수 있다. 기존 상세 시안의 ‘삭제는 웹에서만 가능’, ‘앱에는 삭제 기능 없음’ 안내와 작업 메모는 현재 사실과 다르므로 해당 DRAFT 안내만 바로잡는다. 삭제는 현재 편집 화면에 있으며, 상세에 새로운 직접 삭제 동작을 발명할 필요는 없다. 다른 홈·문서함·상세 레이아웃과 완료된 페이지는 보존한다.

## 목표와 화면 경계

직원이 필요한 양식을 고르고 내용을 입력한 뒤 **임시저장 또는 상신**하게 한다. 본인의 임시저장은 수정·상신·삭제, 회수 문서는 수정·재상신할 수 있다. 입력 유지와 처리 결과 확인이 우선이며, 장식적 여백이나 대형 소개 카드로 폼 시작을 밀지 않는다.

- `/drafts/new`: 새 기안. `/drafts/[id]`: 본인의 DRAFT/RECALLED 수정. 상단 Stack 헤더는 새 기안/기안 수정, 뒤로 이동이 있다. 이 화면에 하단 탭바를 추가하지 않는다.
- 내용 순서는 간결한 화면 제목·작성 복구/허용된 삭제 → 문서 양식 → 제목 → 양식별 입력 → 결재자 → 첨부파일. 임시저장·상신은 입력과 함께 찾기 쉬운 하단 행동으로 둔다.
- 작성 복구는 기존 `/drafts/recovery`의 진입·복원·현재 편집기로 돌아오는 흐름만 설계한다. 독립적인 복구함 전체 재설계는 범위 밖이다.
- 실제 양식은 서버에서 내려온다. 템플릿 필드 유형·옵션·필수·조건부 노출을 지원하며 고정 폼 하나만 완성한 것으로 처리하지 않는다.
- 대시보드/목록의 첫 행 40% 목표를 폼에 강제하지 않는다. 정확한 입력, 현재 위치, 오류와 다음 행동이 이해되어야 한다.
- 검토용 상태·화면 크기·테마·큰 글자·가상 키보드 컨트롤은 전화기 화면 밖에 둔다.

## 업무 규칙을 보존할 설계

| 상태 | 실제 허용 행동 |
| --- | --- |
| 새 기안 | 임시저장, 상신, 작성 복구. 서버 문서 삭제 없음 |
| 본인의 DRAFT | 임시저장, 상신, 삭제 확인, 작성 복구 |
| 본인의 RECALLED | 수정 임시저장, 재상신, 작성 복구. 문서 삭제 없음 |
| 다른 작성자/편집 불가 상태/계정 검증 실패 | 폼 내용 숨김, 저장·상신·첨부·삭제 차단 |

상신 결재자는 활성 시설장 1명이며 본인을 제외한다. 한 명만 있으면 현재 앱처럼 미리 선택할 수 있다. 후보가 없으면 이유를 보여주고 상신을 막되 임시저장은 가능하다. 임의의 다단계 결재선·대리 상신·완료 문서 편집을 추가하지 않는다.

임시저장은 미완성 입력을 보존하는 행동이다. 상신은 필수 입력·제목·내용·결재자를 검증하고 최종 확인을 거친다. 오류 후 입력을 유지하고 해당 필드/오류 요약에 접근하게 한다. 양식 변경 시 그 양식의 입력값 초기화를 확인하고, 취소하면 입력을 보존한다.

첨부 한도·허용 확장자는 서버 정책을 표시한다. 파일 선택 취소, 업로드 실패, 저장 실패가 다른 입력을 지우지 않게 한다. 저장된 첨부 제거는 영구 삭제 확인, 아직 고르기만 한 파일은 선택 해제로 구분한다. 업로드 진행과 서버 저장 여부를 분명히 보여준다.

저장/상신 처리 중 충돌하는 업무와 중복 실행을 막는다. 결과가 불명확하면 성공/실패를 추정하거나 새 요청을 만들지 않고 **원 요청 결과 확인**을 제공한다. 허용 조건에서만 같은 요청 재시도다. 다른 기기에서 변경되면 현재 입력을 보존한 채 최신 서버 상태를 확인하고 적용/교체를 명시적으로 선택한다.

삭제 확인은 문서 제목, 문서·첨부의 영구 삭제, 화면의 미저장 입력과 해당 문서의 기기 보관본도 삭제되어 복구할 수 없음을 알린다. 취소·뒤로·Escape는 삭제하지 않는다. 처리 중 중복 실행을 막고 불명확한 응답에는 입력을 유지한 **삭제 결과 확인**을 둔다. 성공은 임시저장 목록으로 복귀하고 목록·건수를 새로 반영한다.

기기 보관/작성 복구와 서버 임시저장은 구분한다. 네이티브에서는 같은 계정의 정확한 작성 범위만 복원하며 첨부파일은 재선택이 필요하다. 브라우저 미리보기는 현재 화면 메모리만 사용해 앱 종료·새로고침 뒤 복원이 불가능하다. 계정 변경·권한 상실 시 이전 입력을 노출하지 않는다. 입력 이탈은 보관하고 나가기/저장하지 않고 나가기/취소로 구분한다.

## 대표 모의 자료

모든 이름·문서·파일은 합성 검수 자료만 쓴다. 주 화면: **직원 김예시 · 새 기안 · 390×844 · 라이트**. 문서 양식 일반 기안서, 제목 ‘10월 공용물품 구매 요청’, 기안 내용 ‘10월 공동 활동에 사용할 공용 소모품을 구매하고자 합니다.\n운영 일정에 맞춰 수량을 확인하고 첨부된 모의 계획서를 참고해 검토해 주세요.’, 결재자 이예시·시설장, 선택한 ‘공용물품_계획서_모의.pdf’ 418KB. 일반 양식은 실제 기본 스키마의 제목/기안 내용/첨부를 사용하되 제목을 중복 렌더하지 않는다.

모의 첨부 정책은 최대 5개·파일당 20MB·pdf/png/jpg로 명시한다. 운영 기본값이라고 주장하지 않는다. 기능 참고 캡처의 pdf-only 정책도 합성 검수 응답이다. 긴 제목은 120자 이내, 긴 내용·파일명·복구 알림은 전체를 읽을 수 있게 한다. 다른 예시로 지출결의서의 지출구분·날짜·금액·조건부 입력과 회의록의 여러 안건을 확인한다.

## 시각·산출물·검수

홈 v2의 공유 토큰·Feather 선형 아이콘·4/8/12/16/24 간격을 따른다. 라이트/다크, 44px 이상 터치 영역, 텍스트 대비 4.5:1·컨트롤/상태 3:1을 확인한다. 카드 장식보다 명확한 레이블·입력·얇은 구획으로 폼을 정리한다. 기능 참고 캡처의 이전 남색 대신 적용된 파랑 체계를 쓴다.

새 페이지 **기안 작성 v1**, 편집 가능한 소스, 모의 상호작용 프로토타입, 주요 상태 캡처와 검수 결과를 준다. 검수 컨트롤로 상태를 묶어도 되지만 다음 기능 경계는 실제로 확인 가능해야 한다.

- 새 기안 비어 있음/입력 완료, DRAFT 수정·삭제 확인/취소/완료/불명확, RECALLED 수정·재상신·삭제 없음.
- 양식 선택·변경 확인, text/textarea/number/date/select/checkbox/조건부 필드, 회의록 안건 추가/제거 확인, 활성 양식/시설장 없음.
- 첨부 선택·선택 취소·정책 위반·업로드 진행/실패·저장된 첨부 제거 확인.
- 임시저장과 상신 검증·확인 취소·진행·성공·실패 후 입력 유지·중복 방지, 불명확한 요청 결과 확인, 최신 버전 충돌 선택.
- 작성 복구·첨부 재선택·기기 보관 실패·이탈 확인, 계정/권한 변경 후 내용 숨김, 초기 로딩/실패/재시도.
- 390×844/360×800, 라이트/다크, 200% 상당 큰 글자, 긴 입력·파일명, 키보드 열린 입력과 마지막 확인. Safe Area 가정 상단 47/24·하단 34/16을 기록한다.

핵심 입력·확인·취소가 키보드/하단 행동에 가려지지 않아야 한다. 확인 창은 긴 메시지만 스크롤하고 행동은 항상 접근 가능하게 한다. 포커스 순서·접근 이름·가로 넘침·입력 보존·대비·중복 실행을 실제 렌더로 확인한다. DOM/가상 키보드 검증과 실기기 OS 검증을 구분하고 확인하지 않은 기기·스크린리더·운영 연동을 완료로 주장하지 않는다. 원본 ZIP과 관찰·측정 결과, 남은 제약을 함께 준다.
