# 기안 작성 디자인용 현재 계약

2026-10-05 · main 7bd6cfe · 설계 참고용. API·저장소·토큰을 프로토타입에 연결하지 않는다. 기술 항목은 디자인 구현 경계이며 일반 직원 화면의 설명문으로 출력하지 않는다.

## 화면과 데이터

- 새 기안 `/drafts/new`, 수정 `/drafts/[id]`, 작성 복구 `/drafts/recovery`.
- GET `/api/mobile/drafts/options`: 활성 `templates[]`와 `approvers[]`, `attachmentPolicy`.
- template: `id`, `name`, `fields[]`, `initialValues`. field: `name`, `label`, `type`, `required`, 선택적 `placeholder`, `helpText`, `options[{label,value}]`, `visibleWhen{field,values}`.
- field 유형은 text/textarea/number/date/select/checkbox/attachments. 제목은 별도 `title` 입력, attachments는 공통 첨부 영역. 서버의 안전한 렌더 필드 목록을 사용해 제목/첨부를 중복하지 않는다. select 값과 레이블을 구분하며 checkbox의 필드 값은 true/false 문자열이다.
- 조건부 필드는 지정된 다른 필드 값이 values에 있을 때만 나타난다. 숨겨진 필드를 필수 오류로 막지 않는다. 날짜 입력은 YYYY-MM-DD, 숫자는 decimal 입력을 제공한다.
- GET `/api/mobile/drafts/[id]`: `id,title,templateId,status,fieldValues,approverIds,updatedAt,attachments[{id,name,size,mimeType}]`. 활성 계정이 작성한 DRAFT/RECALLED만 편집 가능하다. 상태를 이름만 보고 추정하지 않는다.
- 기본 일반 양식은 제목/기안 내용/첨부이며 서버는 제목을 별도 렌더 항목과 분리한다. 지출결의서에는 지출구분, 지출일자/구매예정일, 예산항목/사업명, 거래처, 결제수단, 지출금액, 지출목적, 세부내역, 첨부 등이 있고 양식 스키마에 따라 달라진다.
- 회의록 agenda/discussion은 안건별 제목·논의 내용의 반복 입력이다. 1~20개, 안건 제목 300자/논의 5000자 한도. 안건 제거를 확인한다. 기존 fieldValues 표현을 유지하며 새로운 API 자료 구조를 가정하지 않는다.

## 작성·결재자·검증

- 제목 최대 120자. 상신 제목은 공백 제거 후 최소 2자, 작성 내용은 서버가 양식 값에서 구성하며 상신 시 10~5000자. 필수·유형·조건부 필드는 서버 검증을 따른다. 개별 필드 최대 5000자이며 모든 필드가 그만큼 허용되는 최종 문서라는 뜻은 아니다.
- 임시저장은 미완성이어도 가능하되 유효한 활성 양식과 입력/첨부 한도는 지킨다. 빈 제목은 서버가 ‘제목 없는 기안’으로 저장한다. 양식/결재자를 새로 만들어 유효한 것처럼 보이지 않는다.
- 상신은 본인 제외 활성 시설장 **정확히 1명**. 한 후보이면 앱에서 미리 선택하며 후보가 없으면 상신 불가·임시저장 가능이다. 관리자라는 이유로 결재 권한을 만들지 않는다.
- 양식을 바꾸면 해당 양식의 `fieldValues`를 새 기본값으로 초기화한다. 변경 확인 취소는 입력 유지. 현재 코드의 제목·결재자·첨부는 유지되며 모든 입력이 삭제된다고 안내하지 않는다.
- 상신은 최종 확인, 회수 문서는 ‘재상신’ 및 결재가 처음부터 진행됨을 안내한다. 성공 후 상세 결과 문서로 연결한다.

## 첨부

- `attachmentPolicy{maxFileCount,maxFileSizeMb,allowedExtensions}`를 응답에서 표시한다. 이미지의 5개/20MB/pdf와 브리프의 5개/20MB/pdf/png/jpg는 각각 모의 검수 응답이지 운영 고정 정책이 아니다.
- 저장된 파일과 새 선택 파일은 합산한 수/한도, 이름·크기·상태를 표시한다. 새 선택 상태 ‘저장 시 업로드’ → ‘업로드 완료’, 기존은 ‘저장된 파일’이다.
- 파일 선택을 취소해도 다른 입력은 유지한다. 한도·형식·크기 위반은 해당 파일/정책 오류를 알린다. 저장/상신 전 업로드 진행 n/m을 제공하며 중복 업무를 막는다.
- 새 선택 파일 제거는 선택 해제, 저장된 첨부 제거는 서버 파일 영구 삭제 확인이다. 브라우저 모의 프로토타입에서 실제 삭제·전송은 하지 않는다.
- 파일 URL·업로드 토큰·저장소 키는 직원 화면이나 로그 캡처에 노출하지 않는다.

## 저장·상신 결과와 충돌

- POST `/api/mobile/drafts` 또는 `/api/mobile/drafts/[id]` body: `requestId,title,templateId,fieldValues,approverIds,uploadIds,intent,expectedUpdatedAt`. intent는 draft/submit. 기존 문서는 읽은 updatedAt을 버전 기준으로 쓴다.
- 요청은 고유 requestId와 원 입력 스냅샷을 유지하며 저장·상신의 중복/충돌을 막는다. 완료 전에 입력이 달라진 경우 후속 입력을 유지하고 계속 작성/결과 확인을 명시적으로 선택한다.
- 응답이 불명확하면 현재 입력과 원 요청 증거를 보존한다. **원 요청 결과 확인**은 GET `/api/mobile/drafts/requests/[requestId]`와 원 문서 범위로 확인한다. 결과 확인 404를 미저장 증거로 간주하지 않는다.
- 서버가 허용한 원 입력·동일 요청의 재시도만 가능하다. 첨부 없는 재현 가능한 요청 등에만 ‘같은 요청 재시도’를 제공한다. 불명확한 응답 뒤 새로운 requestId로 자동 저장/상신하지 않는다.
- 버전 충돌은 ‘최신 내용 확인’ 후 **입력 유지·최신 기준 적용 / 서버 내용으로 교체**를 직접 선택한다. 최신 버전을 자동 채택해 기존 입력을 덮어쓰거나 자동 재상신하지 않는다.

## 서버 임시저장 삭제 — 배포 완료

- DELETE `/api/mobile/drafts/[id]` body `{expectedUpdatedAt}`. 본인의 DRAFT만 허용한다. 새 기안·RECALLED·다른 사람·상신/완료 상태에는 삭제 없음.
- 삭제 전 서버 상태/권한/버전을 다시 확인한다. 다른 버전을 자동 채택하지 않는다. 오래된 버전은 409, 권한 없는/없는 문서는 내용을 드러내지 않는다.
- 확인: 문서와 첨부의 영구 삭제, 현재 화면 미저장 입력과 해당 문서의 기기 보관본도 제거되어 복구 불가. 업무 감사 기록은 유지하지만 내부 감사 메타를 노출하지 않는다.
- 삭제 처리 중 저장/상신/복구/재삭제 등 충돌 행동을 차단한다. 취소는 변화 없음. 불명확한 결과는 입력을 유지한 ‘삭제 결과 확인’으로 동일 버전 삭제를 확인한다. 이미 처리된 동일 버전의 결과 재확인은 서버가 멱등 처리한다.
- 명확한 실패는 메시지/최신 상태 확인으로 처리하며 성공처럼 보이지 않는다. 성공 시 `/drafts?folder=drafts`로 복귀하고 목록·건수를 새로 조회한다.
- 기존 상세 시안의 ‘모바일 삭제 불가/웹에서만 삭제’ 안내는 폐기한다. 상세는 기존 편집 진입을 유지하면 되며 직접 삭제 API 연결을 추가할 필요는 없다.

## 작성 복구·계정 보호

- 서버 임시저장과 기기 보관은 서로 다르다. 네이티브 기기 보관은 OS 보호 저장소, 브라우저는 현재 화면 메모리뿐이다. 브라우저 새로고침/종료 후 복원 가능하다고 말하지 않는다.
- 계정과 정확한 작성 범위(새 기안 세션 또는 원 문서)에 묶인다. 제목/양식/필드/결재자/버전/원 요청 확인 정보는 보관할 수 있으나 **첨부파일은 보관하지 않으므로 재선택**해야 한다.
- ‘보관 입력 복원’, 입력 없는 증거는 ‘요청 확인 정보 열기’, ‘보관 내용 버리기’는 해당 범위 제거 확인. 다른 계정의 내용을 보여주지 않는다.
- 보관 실패/한도 초과는 현재 입력을 유지하고 실패를 안내한다. 자동으로 다른 기안/계정 보관본을 삭제하거나 입력을 잘라 넣지 않는다.
- 앱이 배경/외부로 전환되면 내용 보호, 다시 진입해 활성 계정·권한을 검증한 후 내용/첨부와 업무 동작을 허용한다. 권한 실패 시 CSS로 가리기만 하지 않고 민감한 이전 입력을 렌더에서 제거한다.
- 이탈 확인은 ‘보관하고 나가기 / 저장하지 않고 나가기 / 취소’. 저장하지 않고 나가기는 현재 범위 기기 보관본 제거이며 서버 문서 삭제와 다르다. 삭제 결과가 불명확할 때는 이미 삭제되었을 가능성을 안내한다.
- Android 선택 목록/확인은 앱 Activity 안에서 처리해 외부 전환 보호와 충돌하지 않게 한다. 디자인 프로토타입의 모달과 실제 OS 동작을 혼동하지 않는다.
