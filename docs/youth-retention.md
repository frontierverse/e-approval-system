# 청소년 퇴소기록 보존·파기

관리자 메뉴의 `/youth/retention`에서 실제 퇴소 확인, 상담·사후관리 완료일, 보존 보류, 사유별 열람, 파기 검토를 처리한다.

## 적용한 기준

- [2026년 청소년사업 안내 2권](https://www.mogef.go.kr/io/ind/io_ind_s005d.do?bbtSn=172&mid=old919) 인쇄 459쪽: 청소년회복지원시설 운영자료는 5년 이상 보존한다.
- 같은 안내 인쇄 418쪽의 동의서 예시: 상담완료일부터 5년을 보유한 뒤 파기한다. 인쇄 467쪽에는 퇴소 후 사후관리 업무가 있다.
- [개인정보 보호법 제21조](https://www.law.go.kr/lsLinkCommonInfo.do?lsJoLnkSeq=1027063705): 목적 달성 등으로 불필요해진 개인정보는 파기하고, 다른 법령에 따라 보존하는 정보는 분리하여 관리한다.

결정문은 법원 위탁의 근거인 공식 사례기록으로 보존하는 운영 판단을 적용했다. 별도의 ‘결정문은 퇴소일부터 정확히 5년’ 규정을 확인한 것은 아니다. 기본 보존기간은 상담·사후관리 완료일부터 5년이며, 만료일 당일까지 보존한다. 윤년 2월 29일은 5년 뒤 2월 말일로 계산한다. 법원 요청, 감사, 미종결 사건 등 추가 보존 근거가 있으면 사유와 재검토 시점을 보존 보류에 등록한다.

## 상태와 접근

- 퇴소 예정일을 실제 퇴소일로 자동 전환하지 않는다. 기존 예정일이 지난 기록은 일반 조회에서 제한하고 관리자 확인 대상으로 표시한다. 실제로 입소 중이라면 ‘입소 유지 · 퇴소 예정일 정정’으로 바로잡을 수 있다.
- 실제 퇴소가 확정되면 일반 명단, 연락처, 일정, 학습진도, 생일·퇴소 알림, 청소년별 업무보고 조회에서 제외한다. 과거 업무보고의 청소년별 항목은 보존 데이터에 남지만 일반 화면으로 전달하지 않는다. 보고서를 수정해도 숨겨진 항목을 덮어쓰지 않는다.
- 관리자만 사유를 선택해 보존 연락처·가족정보·결정문·특이사항·제출된 청소년별 업무보고를 열람한다. 개인 초안은 열람 DTO에 포함하지 않는다. 감사기록 저장이 실패하면 민감정보와 다운로드 응답을 반환하지 않는다.
- 미정산 수학 보상은 관리자 정산 화면에서 처리할 수 있다. 계산에는 확정된 실제 퇴소일을 우선 사용한다. 파기를 시작한 대상의 정산 변경과 일반 업무 수정은 차단한다.
- 실제 퇴소일은 확정 후 수정하지 않으며, 이미 등록한 상담·사후관리 완료일은 앞당기거나 삭제하지 않는다. 사후관리 진행 중에는 완료일을 비워 둔다.

## 파기 범위와 재시도

실제 퇴소, 상담·사후관리 완료, 보존기간 경과, 보존 보류 없음, 필요한 보상 정산 확정을 확인한다. 관리자는 자유서술·외부 사본·백업과 추가 보존 필요성을 점검하고 대상 이름을 직접 입력해야 한다. 자동 파기는 하지 않는다.

처리 순서는 접근 차단 및 처리 잠금 → 결정문 저장소 파일 삭제 → DB 개인정보 제거다. 파일 삭제 실패 시 참조와 개인정보를 유지하고 일반 접근을 차단한 채 재시도할 수 있다. DB 처리 실패도 완료로 표시하지 않는다. 5분 처리 잠금과 버전 비교로 중복 처리를 막는다. 청소년 행 잠금으로 퇴소·파기와 일반 업무 수정의 경합을 제어한다.

파기는 기본정보, 가족 연락처, 결정문 파일과 메타데이터, 특이사항, 연장 이력, 개별 일정·학습·규칙·개념 체크, 업무보고의 연결된 청소년별 항목, 연결된 감사기록의 개인 내용과 보상 메모를 제거한다. 업무보고 버전을 올려 오래된 편집 화면의 재저장을 차단한다. 익명 표식과 확정된 정산 금액·감사행위 정보는 유지한다. 내부 식별자는 연결 일관성을 위해 남으므로 이를 완전한 익명화의 법적 보증으로 취급하지 않는다.

일반 업무보고 본문, 업무일지, 결재문서·첨부, 채팅처럼 청소년 ID와 연결되지 않은 자유서술은 자동 수정하지 않는다. 외부 사본과 백업도 이 기능만으로 삭제되지 않는다. 관리자가 별도 삭제·접근 제한·보존 근거를 확인하고, 백업 복원 시 파기 대상이 재노출되지 않도록 파기 이력을 반영해야 한다. 점검되지 않은 자료가 있으면 파기를 진행하지 말고 보존 보류에 사유를 등록한다.

## 배포와 검증

추가 마이그레이션: `prisma/migrations-postgresql/20261001120000_add_youth_retention/migration.sql`. 기존 날짜를 실제 퇴소일로 추정하거나 기존 자료를 삭제하는 SQL은 없다. 정산 확인에 필요한 `20260928120000_add_math_rewards`와 해당 테이블의 서버 전용 접근을 보장하는 `20261002021000_enable_math_reward_rls`도 함께 적용한다. 배포 전에 DB 백업·대상을 확인하고, `npx prisma migrate status`로 다른 미적용 변경을 확인한 뒤 프로젝트 표준 절차인 `npm run db:deploy`, `npm run db:generate`, 애플리케이션 배포를 진행한다. 새 코드는 해당 컬럼이 적용된 DB를 요구한다.

실제 서비스·DTO·다운로드 경로를 격리된 트랜잭션 저장소로 테스트한다. 실제 PostgreSQL 및 외부 저장소 연동 검증은 배포 환경에서 필요하다. 브라우저 검수는 실제 `YouthRetentionBoard`와 로딩 컴포넌트를 사용하는 가짜 데이터 페이지에서 수행한다.

```sh
node --import ./tests/tsx-loader.mjs --test --experimental-test-isolation=none tests/youth-retention.test.mts tests/daily-reports.test.mts
npx playwright test --config playwright.retention.config.ts
```

브라우저 기준은 1366×768, 390×844, 작은 모바일 320×800, 다크 모드와 200% 확대다. 요약 건수와 우선 처리 기록, 검색·빈 상태·로딩, 가로 넘침, 모달 포커스·닫기·복귀, 오류 입력 보존, 중복 저장 방지, 파기 확인을 검수한다.

2026-10-01 검수 결과: 실제 보드 컴포넌트의 격리 페이지에서 데스크톱 1366×768과 모바일 390×844 모두 요약 건수와 파기 검토·퇴소 확인 대상이 첫 화면에 표시되었다. 목록은 각각 상단 약 206px·280px에서 시작한다. 320px 다크 모드와 200% 확대까지 가로 넘침이 없고, 브라우저 테스트 8개가 통과했다. 전체 단위 테스트는 945개 통과·3개 건너뜀, 변경 파일 ESLint와 프로덕션 빌드도 통과했다. 운영 DB 권한·마이그레이션 및 실제 저장소 파일 삭제를 이 결과로 검증한 것은 아니다.

2026-10-02 운영 반영 검증: 운영 환경의 Supabase 프로젝트와 마이그레이션 이력을 Vercel 빌드에서 대조했다. 청소년 테이블 11건은 Windows 사용자에 묶인 암호화 백업으로 저장하고 메모리 복호화·체크섬으로 복구 가능성을 확인했다. 세 마이그레이션 적용 후 원래 컬럼의 전체 데이터 체크섬이 일치했고, 실제 퇴소일·완료일·파기 상태는 모두 미설정으로 유지됐다. 신규 정산 테이블 5개는 RLS가 활성화되어 있고 클라이언트 API 역할에 조회 권한이 없다. 이 확인은 청소년 테이블 백업이며 전체 DB·첨부파일 백업을 대체하지 않는다.

기존 운영 커밋에서 이번 기능만 분리한 배포본은 단위 테스트 909개 통과·기존 3개 건너뜀, ESLint·타입 검사, 브라우저 8개와 Vercel 운영 빌드를 통과했다. 기존 모바일 서버 API도 배포에 포함한다. `.vercelignore`의 `/mobile/`은 저장소 루트의 앱 소스만 제외하므로 서버의 `src/app/api/mobile` 경로를 제외하지 않는다. 운영 DB 연결과 비로그인 접근 제한은 도메인 전환 전후에 확인한다. 실제 청소년 기록 파기는 실행하지 않았다.

`scripts/check-youth-retention-release.mjs`는 읽기 전용 사전 확인용이다. `RETENTION_EXPECTED_PROJECT_REF`를 검토한 Supabase 프로젝트 참조로 설정하고, 필요하면 `RETENTION_EXPECTED_MIGRATION_DIGEST`를 사용해 확인한 이력과 일치하도록 제한한다. 운영에서 누락된 두 과거 마이그레이션의 이력은 수정하거나 재적용하지 않았다.
