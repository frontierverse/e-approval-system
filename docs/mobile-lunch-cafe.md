# 모바일 급식·카페와 공용 카페 변경 정책

앱의 내 정보 → 급식·카페에서 날짜별 급식 메뉴를 조회하고, 카페 물품·변경 이력·준수사항을
확인한다. 카페 물품은 등록·수정·삭제와 유통기한 경과 식품의 보류 사유 등록을 지원한다.
준수사항은 등록·삭제한다. 모든 ACTIVE 직원에게 기존 웹과 같은 공용 접근을 적용한다.
ADMIN·시설장·작성자만 관리하도록 권한을 바꾸지 않는다.

## 급식 메뉴

`GET /api/mobile/meal-menu?date=YYYY-MM-DD`는 기존 메뉴와 활성 학교의 해당 날짜 수량을
하나의 조회 스냅샷으로 읽는다. 날짜는 0001년부터 9999년까지 유효한 그레고리력 날짜다.
메뉴가 없는 날짜는 빈 메뉴이며, 조회 오류를 빈 메뉴로 표시하지 않는다.

학교별 총수량과 전체 총수량은 기존 일곱 수량 항목의 합계다. 보존식과 배송기사 수량이
포함된다. 등록된 수량이 없는 활성 학교는 0으로 표시한다. 준비 체크·학교 관리·수량 수정·
고용비·구매지출·메뉴 편집·외부 메뉴 동기화·서명·인쇄는 이 모바일 기능에 포함하지 않는다.
조회 GET은 준비 여부나 감사 기록을 변경하지 않는다.

## 카페 조회

물품 목록은 분류·상태·등록순/유통기한순·검색·보류 여부로 조회하고 20개씩 나눈다.
유통기한 경과는 오늘 이전, 30일 이내는 오늘부터 30일 뒤까지이며, 식품 이외의 구매 100일
이상은 구매일부터 계산한다. 기준일은 서버가 요청마다 계산한 한국 날짜다.
보류 물품도 유통기한 경과 건수에 포함된다. 상단 요약은 전체 물품 기준이고 목록의 검색
결과 건수와 구분한다. 가격 0원과 가격 미등록은 다른 값이다.

`/api/mobile/cafe/items`, `/items/[id]`, `/history`, `/notes`는 현재 ACTIVE 계정을 다시 확인한
뒤 읽는다. 변경 이력은 카페 물품의 작업만 제공하며 직원명·물품명·표준 작업 문장을 반환한다.
이메일·접속 정보·원본 감사 메타데이터는 반환하거나 검색 조건으로 쓰지 않는다.
삭제된 물품의 이력도 해당 물품 ID로 조회할 수 있다. 준수사항의 작성자가 삭제되면 작성자
정보가 비어 있는 정상 자료로 표시한다. 자료실·청소년의 열람 또는 파일 영수증을 사용하지 않는다.

## 공유 변경 도메인

웹 카페와 모바일은 `mutateCafe`의 여섯 작업을 공유한다. 작업은 물품 등록·수정·삭제·보류,
준수사항 등록·삭제로 고정한다. 물품의 기존 감사 기록과 업무 변경, 요청 영수증은 같은
트랜잭션에서 처리한다. 준수사항에는 기존 정책대로 별도 감사 기록을 추가하지 않는다.

수정·보류·삭제는 화면에서 확인한 정확한 `updatedAt` 기준을 보낸다. 서버는 현재 계정·대상 행을
잠근 뒤 기준을 대조한다. 동시 수정 시 입력을 유지하고 최신 내용을 명시적으로 확인한 뒤
새 기준을 선택한다. 동일 밀리초에 변경해도 기준 시각은 이전보다 증가한다.
유통기한 보류는 현재 경과한 식품에만 적용하며 식품 분류나 기한을 수정하면 기존 웹의
보류 사유 유지·해제 규칙을 적용한다. 별도 보류 해제나 물품 수량·배정 기능은 추가하지 않는다.

`CafeMutationReceipt`는 직원 ID·안정된 요청 키·작업·대상 ID·본문 해시·원래 완료 시각과
수정 기준만 보관한다. 같은 키의 같은 요청은 영수증을 먼저 확인하고 업무·감사를 반복하지 않는다.
같은 키에 다른 요청을 보내면 거절한다. 대상이 삭제되더라도 이전 등록 요청으로 다시 만들지 않는다.
원래 완료 시점의 증거와 현재 대상의 내용은 구분한다. 영수증 조회는 본인 요청만 허용하며
자료를 변경하지 않는다. 요청 기록의 부재만으로 진행 중인 요청이 미처리됐다고 단정하지 않는다.

화면은 동기적인 제출 잠금과 원래 요청의 입력·키·수정 기준을 유지한다. 통신 결과가 불명확하면
처리 결과를 먼저 조회하고, 명시적인 재시도만 같은 요청으로 보낸다. 삭제에는 대상 확인이 필요하다.
저장 이후 화면 갱신 실패는 이미 완료된 업무 결과를 되돌리거나 중복 작업을 발생시키지 않는다.

## 계정·응답·배포

앱의 조회 범위는 계정·세션·날짜·필터·페이지·물품 ID에 묶는다. 늦게 도착한 이전 조회가
새 범위의 화면을 덮어쓰지 않도록 중단·세대 확인을 적용한다. 화면 진입과 전경 복귀는 인증된
새 조회를 수행한다. 계정 변경이나 인증 상실 시 입력과 조회를 새 계정에 섞지 않는다.
급식·카페 본문은 기기에 영구 저장하지 않는다.

모바일 응답은 성공과 실패 모두 private/no-store, Authorization/Cookie Vary, nosniff를 적용한다.
조회 조건과 JSON 항목은 고정하며 중복 항목을 거절한다. 변경 본문은 실제 바이트 기준
64KiB와 전체 읽기 시간 10초로 제한한다. 서버 내부 오류나 비밀값을 그대로 반환하지 않는다.

추가 마이그레이션은 `20261004050000_cafe_mutation_receipts`이며 서버 전용 요청 영수증
테이블 하나만 만든다. 직원·물품·준수사항의 외래키나 삭제 연동을 두지 않고, RLS를 켜되 공개
Data API 정책은 만들지 않는다. 기존 업무 데이터와 과거 마이그레이션 이력은 보존한다.
운영 배포 전 검증된 소스·CI·DB 대상·단일 대기 마이그레이션을 확인하고 표준 migrate deploy를
사용한다. 운영 DB에 seed, migrate dev, db push를 실행하지 않는다.

실제 화면 검수와 자동 검증은 구현 완료 기록에서 별도로 확인한다. 합성 데이터의 RN Web 검수는
실기기 동작이나 운영 권한 확인과 구분하며, Android·iOS 게시 후에는 정확한 업데이트 ID와
기존 runtime, 실제 배포 자산의 해시를 확인한다.
