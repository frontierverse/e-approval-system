# Claude Design 전달 바자울 모바일 알림 v1

기준일 **2026-10-05 한국시간**, 운영 main **c891eee / PR #27**. 기존 Claude 작업 **바자울 전자결재 앱 디자인**의 새 페이지 **알림 v1**을 만든다. 홈 v2·문서함 v1·문서 상세 v1·기안 작성 v1·받은결재 v1은 실제 앱에 적용했고 서버와 Android·iOS production OTA 배포를 마쳤다. 이번 요청은 알림 목록의 디자인과 검토용 모의 프로토타입이다.

## 목적과 범위

직원이 읽지 않은 결재 소식을 빠르게 확인하고, 필요한 기존 문서 상세로 들어가거나 알림을 읽음으로 표시하게 한다. 기존 HomeTheme와 Feather 선형 아이콘을 이어간다. 완료한 다른 페이지는 보존한다. 알림 목록에서 새 문서 상세·결재 기능·푸시 설정 화면을 만들지 않는다.

첨부는 이 브리프, 프로젝트 UI/UX 가이드라인, 최신 기능 계약, 적용된 화면의 스타일, 현재 알림의 기능 참고 캡처다. 최신 계약을 과거 시안의 가정보다 우선한다. 현재 알림 캡처의 이전 남색·테마는 기능 참고이며 새 시안의 스타일 기준은 적용된 HomeTheme다.

운영 API·실제 로그인·직원 정보·업무 문서·푸시 등록·앱 소스·DB·배포를 사용하거나 변경하지 않는다. 이름·알림·문서·사유는 아래의 합성 자료만 쓴다.

## 사용자와 권한

- 알림 탭은 로그인한 **모든 직원**이 사용한다. 시설장 전용 화면이 아니다. 관리자도 본인 알림만 보며, 관리자 역할로 다른 직원 알림이나 무관한 문서를 열 수 없다.
- 목록·건수·읽음 처리는 **본인에게 전달되었고 지금 열람 가능한 문서의 알림**만 포함한다. 현재 열람할 수 없는 문서의 알림은 목록과 건수에서 제외한다.
- 행의 문서 열기는 서버의 최신 문서 열람 확인 및 읽음 처리 성공 후에만 기존 상세로 이동한다. 사라졌거나 접근할 수 없는 문서는 같은 일반적인 오류로 안내하고 내용을 추측하거나 공개하지 않는다.
- 세션 만료·계정 변경·권한 확인 실패에서는 이전 계정·권한의 목록과 건수를 제거한다. 이는 새 시안의 안전 기준이며 현재 화면에 모든 처리가 이미 구현되었다는 뜻은 아니다.

## 첫 화면과 정보 밀도

작은 헤더의 **알림 / 전체 읽음**, 간결한 **안 읽음 n건 · 전체 n건**, **전체/안 읽음** 필터와 갱신 행동, 바로 이어지는 업무 행이 핵심이다. 같은 건수를 큰 카드나 중복 제목으로 반복하지 않는다. 첫 업무 행은 기본 390×844에서 Safe Area·전역 탭바를 제외한 콘텐츠 상단 40% 이내로 시작하게 한다.

`unreadCount`는 현재 페이지에 보이는 안 읽음 행 수가 아니라 **본인의 열람 가능한 모든 미읽음 알림 수**다. 전체 필터의 `total`은 전체 알림 수, 안 읽음 필터의 `total`은 안 읽음 결과 수다. 안 읽음 필터에서 그 total을 전체 알림으로 표시하지 않는다. 알림 수는 문서 수·대기 결재 수와 다르다. 같은 문서에 알림이 여러 개 있을 수 있다.

아직 조회하지 못한 건수를 0으로 만들지 않는다. 최초 로딩과 통신 실패에서는 ‘확인 중’ 또는 확인할 수 없음을 알린다. 마지막으로 확인한 건수·행을 유지하는 재조회 실패는 이전 결과임을 작게 표시한다. 큰 숫자에는 숫자 정렬을 쓰되 레이아웃이 겹치지 않게 한다.

## 알림 행

행은 **알림 제목 → 메시지 → 생성 시각·읽음 상태** 순서로 읽힌다. 제목과 메시지는 서버가 준 일반 텍스트다. 긴 한글 제목·메시지와 반려 사유가 버튼을 밀어내거나 가로로 넘치지 않아야 한다. 줄임표를 쓰면 문서 열기 접근 이름에서 대상을 구분할 수 있게 한다. 읽음 여부는 색뿐 아니라 글자·무게·접근 이름으로 전달한다.

반복 행은 약 64~88px을 시작점으로 삼되 큰 글자나 긴 내용을 잘라 맞추지 않는다. 매 행에 큰 카드·아바타·별도 큰 ‘보기’ 버튼을 넣지 않는다. 문서 여는 영역과 미읽음 행의 **읽음으로 표시** 행동은 별개이고 둘 모두 44×44px 이상의 터치 영역과 명확한 접근 이름이 필요하다.

행 응답에는 알림 유형 enum, 문서 상태, 기안자 별도 필드, 문서번호, 첨부 개수, 금액, 긴급도, 현재 결재 가능 여부가 없다. 제목·메시지를 파싱해 추가 통계나 상태 칩을 만들지 않는다. 서버 제목 ‘내 결재 차례’도 알림을 생성한 시점의 소식이다. 모든 행에 ‘지금 승인 가능’을 덧붙이지 않는다. 최신 처리 가능 여부는 기존 상세에서 확인한다.

시각은 `createdAt`을 한국 시간으로 표시한다. 과거 연도를 혼동하지 않게 연도를 유지하고, 실제 날짜 없이 ‘방금/오늘’ 같은 값을 만들지 않는다. 읽음 시각은 상태 판단에 쓰지만 생성 시각을 덮어쓰지 않는다.

## 실제 행동과 모의 동작

- **전체/안 읽음** 변경은 해당 필터 1페이지로 간다. 최신 생성 시각순만 지원하며 같은 시각이면 ID 내림차순이다. 검색·기간·유형 필터·정렬 메뉴·오늘/어제 분류 탭을 새 기능으로 만들지 않는다.
- **개별 읽음**은 그 알림 한 건만 처리한다. 전체 필터에서는 행을 유지하고 읽음 상태/행동을 갱신한다. 안 읽음 필터에서는 해당 행이 빠지고 서버 결과로 목록·건수·페이지를 다시 맞춘다.
- **전체 읽음**은 현재 화면의 20건만이 아니라 모든 페이지에 있는 본인 열람 가능 미읽음 알림을 처리한다. 알림이나 문서를 삭제하지 않는다. 현재 기능은 즉시 실행이며 별도 확인창과 되돌리기 API는 없다. 불필요한 파괴적 경고·모의 삭제·‘읽지 않음으로 되돌리기’를 추가하지 않는다.
- 전체 읽음 성공 뒤 새 알림이 도착하면 반환 `unreadCount`가 0이 아닐 수 있다. 숫자를 무조건 0으로 만들지 않는다. 알림 제목에 ‘승인 완료’가 있어도 읽음 처리 자체는 승인 행동이 아니다.
- **문서 열기**는 단순 행 클릭 이동이 아니다. 서버가 문서 열람을 확인하고 **같은 문서의 본인 미읽음 알림들을 모두** 읽음 처리한 뒤, 반환 미읽음 수를 반영하고 기존 `/documents/:id` 상세로 이동한다. 이미 읽은 행에서도 같은 권한 확인을 수행한다. 실패하면 목록에 머물고 재시도를 제공한다.
- 읽음·전체 읽음·문서 열기 진행 중 연타와 서로 겹치는 변경을 막고 어느 작업인지 표시한다. 성공은 작은 피드백과 건수/목록 변경으로, 실패는 행동별 오류와 해당 작업 재시도로 보여준다. 성공을 서버 응답 전에 단정하지 않는다.
- 상세에서 돌아오면 원래 필터·페이지를 유지하고 갱신한다. 필터나 계정이 바뀐 뒤 늦은 조회/읽음/문서 열기 응답이 현재 목록·건수·이동을 덮어쓰지 않게 한다.

## 페이지 이동과 상태

페이지 크기는 **20건**, 무한 스크롤은 아니다. 2페이지 이상에서 이전/현재·전체 페이지/다음을 제공하고 처음·마지막·조회/처리 중 해당 행동을 비활성화한다. 미읽음 처리로 마지막 페이지가 사라지면 서버가 반환한 실제 페이지로 보정한다. 0건은 서버상 1/1이며 빈 화면에서 무의미한 페이지 도구를 반복하지 않아도 된다.

최초 로딩, 전체 0건, 미읽음 0건, 최초 연결 실패, 같은 조건 재조회 실패와 이전 결과 안내, 개별/전체 읽음 진행·성공·실패·재시도, 문서 열기 진행·실패, 404, 세션 만료, 계정 변경을 설계한다. 빈 상태를 오류로 보이게 하지 않는다. 다른 필터 결과를 현재 필터 아래에 보여주지 않는다. 알림 수신·앱 복귀·탭 재방문·당겨서 갱신·새로고침의 목록과 배지 갱신을 모의로 확인한다.

## 탭바와 스타일

시설장: **홈 → 받은결재 → 문서함 → 알림 선택 → 내 정보**. 일반 직원 및 시설장이 아닌 관리자: **홈 → 문서함 → 알림 선택 → 내 정보**. 받은결재 존재 여부는 `canApproveDocuments`로 정한다. 알림 배지는 1~99는 숫자, 100 이상은 99+, 0 또는 미확인은 숨기며 접근 이름에는 실제 미읽음 수를 전달한다. 미확인과 0을 같은 확정 상태로 설명하지 않는다.

HomeTheme의 흰/어두운 표면·얇은 테두리·절제된 파란 선택/주 행동, Feather 선형 아이콘, 기존 탭 선택 배경과 Safe Area를 보존한다. 실제 OS 상태바를 장식으로 이중 생성하지 않는다. 푸시 켜기/끄기 및 OS 설정은 이미 **내 정보**에 있다. 이번 목록에 알림 권한 배너나 새 설정 섹션을 넣지 않는다.

## 합성 예시와 산출물

메인: 시설장 **이예시**, 390×844 라이트, 전체 필터, **전체 23건·안 읽음 3건·1/2페이지·20행**. 앞 3행은 미읽음, 나머지 20행은 읽음이다. 앞 1·2행은 같은 `qa-alert-doc-1` 문서, 3행은 다른 문서다. 계약 문서의 정확한 6개 필드를 쓴다. 첫 행 개별 읽음 후 2건, 초기 상태에서 첫 행 문서 열기 후 1건으로 감소하는 차이를 검토할 수 있어야 한다. 일반 직원 김예시의 4탭 변형도 제공한다.

추가 모의 상태: 1건, 전체 0건, 전체는 있으나 미읽음 0건, 긴 제목·메시지, 100+ 배지, 미읽음 22건의 마지막 페이지 보정, 전체 읽음 뒤 새 알림 1건, 중복 실행 방지, 늦은 응답, 계정·권한 변화. 상태·크기·테마·큰 글자·모의 네트워크 컨트롤은 **앱 화면 밖**에 둔다. 실제 API로 테스트하지 않는다.

완성된 **알림 v1** 페이지, 첫 메인 캡처, 주요 상태 캡처, 동작하는 검토용 프로토타입, 편집용 소스 ZIP, 실제 검수 결과를 제공한다. 단순 목업에 없는 동작을 검수 통과했다고 적지 않는다.

## 완료 검수

- 390×844·360×800, 라이트·다크·200% 상당 큰 글자를 실제 렌더로 확인한다. 제목/건수/읽음 버튼/필터가 겹치지 않고 가로 넘침·44px 미만 영역·누락된 접근 이름이 없어야 한다.
- 기본 첫 행 시작이 콘텐츠 상단 40% 이내이며 로딩·빈 상태·오류도 같은 밀도를 유지한다. 글자 확대 시 읽기와 작업 안전을 우선한다.
- 두 필터의 건수 의미, 20건 페이지, 0건과 미확인, 같은 문서 복수 알림, 개별/전체/문서별 읽음 범위를 확인한다.
- 읽음 뒤 목록 제거/유지, 배지, 실제 페이지 보정, 전체 읽음 뒤 신규 알림, 원래 필터·페이지 복귀를 확인한다.
- 연타 시 한 번 실행, 실패 뒤 미확정 성공 금지와 재시도, 필터 변경의 늦은 응답 방지, 계정/권한 변경의 이전 데이터 제거를 확인한다.
- 문서 열기 실패 시 목록 유지와 일반 오류, 서버 확인 성공 뒤 기존 상세 연결을 모의로 확인한다. 새 상세나 결재/삭제/푸시 설정을 만들지 않는다.
- DOM 검수·화면 배율·모의 상태와 실제 iOS/Android·기기 글자 크기·스크린리더·OS 푸시·운영 API 검증을 구분한다. 실기기 미확인은 그대로 기록한다.

## 실제 앱 적용 기록 — 2026-10-05

위의 main c891eee와 모의 디자인 범위는 Claude 요청 당시의 기록이다. 완료된 **알림 v1** 편집 소스 `bajaul-notifications-v1-source.zip`와 대표 390×844 캡처를 실제 Expo NotificationsScreen에 반영했다. HomeTheme, 작은 헤더/필터, 그룹형 행, 미읽음 점·굵기·문구와 별도 읽음 버튼을 적용하고 한국 시간 연도를 유지한다.

실제 조회/읽음은 기존 API를 사용한다. 계정·조건·포커스가 달라진 늦은 응답 차단, 중복 실행 방지, 문서 열기 도중 이탈 후 이동 취소, 401/403/404의 이전 정보 제거, 갱신 실패의 실제 조회 시각, 마지막 페이지 보정과 작업별 재시도를 보강했다. 문서 열기는 권한 확인·같은 문서 알림 읽음 성공 후 기존 상세로 이어진다.

관련 47개 테스트, 모바일/루트 ESLint·TypeScript, Android/iOS/web Expo export와 실제 합성 브라우저 검수를 완료했다. 비교와 한계는 [design-qa.md](../design-qa.md)에 기록했다. 운영 API·푸시 등록을 검수에 사용하지 않았으며, 이 기록은 PR 병합이나 production OTA 배포를 뜻하지 않는다.
