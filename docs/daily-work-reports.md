# 일일 업무보고

경로: `/work-schedule/daily-reports` (업무 관리 → 일일 업무보고)

- 시설장 직책을 제외한 재직 직원이 날짜마다 한 건을 작성한다. 관리자 계정이어도 시설장 직책이 아니면 직원 작성 화면을 사용한다.
- 상단 주요 업무보고는 제출할 때 필수다. 청소년별 활동·대화·생활 관찰 기록은 선택 사항이며, 빈 항목은 저장하지 않는다.
- 임시저장은 본인만 조회한다. 제출한 보고서는 시설장이 날짜별·직원별로 확인한다. 다른 직원에게는 전송하지 않는다.
- 시설장은 미확인 보고를 먼저 보고, 직원·청소년·본문 검색과 제출 상태 필터를 사용한다. 직원 행을 펼치면 전체 본문과 청소년별 기록이 나온다.
- 시설장이 확인 완료로 표시한 후 직원이 수정 제출하면 미확인으로 돌아간다. 이미 제출한 보고는 임시저장 상태로 되돌리지 않는다.
- 하루 한 건의 제약, 버전 비교 및 트랜잭션으로 중복·동시 수정 충돌을 방지한다. 오류 시 입력을 유지한다.
- 이전 날짜 보고서는 계속 보관하며 삭제 UI를 제공하지 않는다. 청소년 이름은 보고서에 보관하여 명단 변경·삭제 이후에도 기록을 유지한다. 수정 전 버전 전체를 별도 보관하는 기능은 포함하지 않는다.
- 수신 가능한 재직 시설장이 없으면 임시저장만 가능하다. 제출 시 서버에서 다시 검사한다.
- 청소년 이름과 ID만 작성 폼에 전달하며 연락처·상세 사례정보를 추가 조회하지 않는다. 새 테이블은 RLS를 활성화하고 직접 클라이언트 접근 정책을 만들지 않는다.

## DB 적용

새 `DailyWorkReport` 테이블을 만드는 마이그레이션은 `prisma/migrations-postgresql/20260914090000_add_daily_work_reports/migration.sql`이다. 기존 업무일지 데이터는 변환하지 않는다.

해당 환경에 애플리케이션을 배포하기 전에 `npm run db:deploy`를 실행하고, `npm run db:generate`로 Prisma 클라이언트를 생성한다. `db:seed`는 초기화용이므로 운영 환경에서 실행하지 않는다.

## 검증

- `tests/daily-reports.test.mts`: 실제 서버 조회·액션 모듈을 격리 저장소로 실행하여 작성 권한, 본인 한정 조회, 임시저장 비공개, 제출·확인·수정, 날짜별 이력, 청소년 스냅샷, 충돌과 트랜잭션 롤백 검증.
- `tests/daily-reports-postgresql.test.mts`: CI의 일회용 PostgreSQL에서 RLS·고유 제약·본문 제약·Prisma 버전 비교를 검증. 로컬 환경에서는 외부 DB를 변경하지 않도록 생략한다.
- `npx playwright test --config playwright.daily-reports.config.ts`: 실제 화면 컴포넌트와 CSS를 격리된 브라우저 fixture에서 검수한다. 앱의 셸 크기를 재현하고 서버 경계에는 합성 데이터를 사용한다.
- 기준 뷰포트: 1366×768, 390×844. 추가로 1440×900, 360×800, 320px 너비, 200% 확대 상당의 683×384 CSS 뷰포트와 라이트·다크 모드를 확인한다.
- 시설장 화면 첫 뷰포트에서 대상·제출·미제출·미확인 수와 직원별 보고 목록을 확인한다. 목록 패널은 셸을 제외한 콘텐츠 뷰포트 상단 40% 안에서 시작한다. 작성 화면에서는 주요 업무 입력이 청소년별 입력보다 먼저 나온다.
- 검색·펼치기·키보드 조작·확인 처리, 빈 상태·로딩·오류, 입력 보존·중복 요청 방지·미저장 이동 취소를 검증한다. 테스트는 주요 컨테이너의 가로 넘침을 검사한다.
- 스크린샷 위치: `outputs/daily-reports/`.
