# 모바일 업데이트 적용 검수 — 2026-10-07

다운로드 완료 후 **업데이트 적용 / 나중에**를 제공한다. 적용을 누르면 준비된 코드로 앱이 재시작한다. 다운로드 이벤트나 화면 진입만으로 재시작하지 않는다. 나중에는 이번 실행의 전역 안내를 숨기고 다운로드를 보존한다. 내 정보 → 앱 업데이트에서 다시 적용할 수 있다.

## 데이터 보호

기존 11개 화면의 이탈 방지 조건을 동일하게 재사용한다. 다른 화면 뒤에 남은 기안·업무일지·일정·할 일·자료·청소년 정보·채팅·급식·카페·일일보고 입력과 확인 중 결재 작업을 보호한다. 로그인·계정 비밀번호·선택한 프로필/서명 이미지와 처리 중 계정 작업도 별도 blocker로 보호한다.

공통 API와 기안·자료·청소년·급식/카페의 상태 변경 요청은 응답 JSON 해석이 끝날 때까지 재시작을 막는다. 성공·실패·중단 후 잠금을 해제하며 GET은 업무 저장으로 취급하지 않는다. 적용이 시작된 뒤 새 상태 변경 요청을 보내지 않는다. 기기 업데이트 기록 저장 후 미저장 입력·앱 foreground·준비 여부·네이티브 처리 상태를 다시 확인한다. native reload 성공 뒤 추가 상태 갱신이나 잠금 해제를 하지 않는다. 실패하면 현재 화면·입력·다운로드를 유지하고 재시도를 허용한다.

## 실제 브라우저 확인

`e2e/helpers/mobile-app-updates-fixture.ts`는 실제 AppUpdatesProvider, 업데이트 화면, 하단 안내, 공용 컨트롤과 테마를 React Native Web으로 렌더한다. Expo/기기 저장소/라우터/아이콘 포트는 합성이고, reload는 호출 횟수를 기록한다. 직원 API는 연결하지 않는다. 기기 글꼴 배율은 Text 크기와 lineHeight를 비례 확대해 모의했다. 운영 데이터나 실제 네이티브 재시작 검증과 구분한다.

- **390×844 라이트:** [적용 대기 화면](ready-light.png). 상태 → 적용/나중에 → 현재 코드 → 기록 순서이며 적용 버튼은 첫 화면에 보인다.
- **320×800 다크:** [작은 화면](ready-small-dark.png). 주 행동과 현재 코드가 읽히고 날짜·기록은 세로로 재배치된다.
- **360×800, fontScale 2:** [큰 글꼴 하단 안내](footer-large-text.png). 발견된 글자 한 개씩 줄바꿈 문제를 수정해 상태 문장이 먼저 전체 너비를 사용하고 버튼이 다음 행에 배치된다. 적용·나중에·상태 보기 모두 접근 가능하다.
- **1366×768 다크:** 기존 최대 720px 내용 폭과 상태 우선순위를 유지한다.
- **200% 확대의 reflow에 해당하는 195×422 CSS 뷰포트:** [하단 안내](footer-zoom-reflow.png). 세 버튼이 두 행으로 흐르며 가로 넘침이 없다. 실제 브라우저 확대 명령이나 실기기 확대를 검증한 것으로 보고하지 않는다.
- 모든 크기에서 document scrollWidth와 div 경계가 뷰포트 안에 있다. 주 행동은 최소 44×44px이고 keyboard focus가 보인다. 화면 제목·접근 이름을 보존한다.
- 실제 provider의 적용, 처리 중 잠금, 실패 후 재시도, 미저장/진행 중 요청 차단, blocker 해제 후 활성화, 나중에 이후 다운로드 보존을 클릭으로 확인했다. 현재 코드 ID는 native 재시작을 모의한 이후에도 성공을 추정해 바꾸지 않는다.
- 기존 두 테마의 색상 토큰과 읽을 수 있는 상태 문구를 재사용했다. 이전 [업데이트 화면 대비 검수](../mobile-app-updates-v1/contrast.json)의 기본 흰색/주 버튼 대비 5.17:1을 유지한다.

## 자동 검증

- 실제 업데이트 provider·페이지·요청·계정 입력 테스트 **44개 통과**.
- 전체 단위 테스트 **2,290개: 2,258 통과, 32 건너뜀, 실패 0**. DB 연결 없는 테스트 URL과 최신 Node 22 패치를 사용했다. PostgreSQL 통합 건은 로컬에서 건너뛰고 PR CI에서 실행한다.
- 브라우저 **9개 통과**: 실제 적용/실패/나중에/보호 조건, 5개 뷰포트·테마·배율 조합.
- 루트·모바일 ESLint와 TypeScript 통과.
- Android/iOS/web production export 통과. 새 의존성·앱 표시 버전·네이티브 구성 변경 없음.

## 남은 검증

Android/iOS 실기기의 실제 JS 재시작, TalkBack/VoiceOver, 시스템 글꼴 배율과 safe area는 미확인이다. 기존 코드에서 이 변경을 처음 받는 경우에는 다운로드 후 한 번 완전히 종료·실행해야 적용 버튼이 생긴다. 이후 업데이트부터 새 흐름을 사용할 수 있다. EAS 운영 업데이트 발행과 실기기 적용은 별도 배포 단계다.
