## 필수 시각 항목

- **글꼴/타이포:** 원본 Noto Sans KR와 앱의 기존 OS 글꼴 차이는 브리프의 플랫폼 글꼴 유지 조건으로 수용했다. 입력 16/23, 본문 16/25, 레이블 14/20·700, 보조 13/19, 작성 내용 제목 15/21·700, 헤더 17·700을 대응시켰다. 웹은 한글 단어 줄바꿈을 보완했고 제목·본문·긴 파일명을 줄 수로 자르지 않는다. 글자 폭·안티앨리어싱·일부 줄바꿈은 플랫폼 차이다.
- **간격/레이아웃:** 좌우 16, 상단 12, 주요 섹션 간격 20, 양식/내용 묶음 14, 입력/패널 반경 12, 입력 최소 48, 결재자 행 최소 52, 보조 행동 최소 44를 확인했다. 하단 임시저장/상신은 1:2 비율이고 좁은 큰 글자에서는 세로로 배치된다. 기본 Stack 헤더의 플랫폼 높이(웹 64)는 시안 52와 달라 내용이 약 12px 아래로 시작한다. 업무 폼에 목록의 첫 행 40% 목표나 탭바를 추가하지 않았다.
- **색/토큰:** 기존 useHomeTheme의 라이트 #F7F8FA/#FFFFFF, 다크 #11151B/#1C222B, 주 행동 #2563EB를 사용한다. 계산 대비: 라이트 본문 16.56:1, 보조 5.81:1, 파랑 행동 5.17:1, 삭제 행동 6.96:1; 다크 본문 14.78:1, 보조 8.00:1. 입력 경계는 라이트 3.23:1·다크 3.19:1이다. 오류는 공용 danger/dangerSoft 의미색으로 대응한다. 비활성 상태는 기존 투명도와 함께 실제 disabled 상태를 제공한다.
- **이미지/아이콘:** 이 화면은 별도 사진·삽화·브랜드 이미지가 필요하지 않는다. 기존 Feather의 파일·첨부·복구·삭제·선택·화살표를 쓴다. 첨부 아이콘 36px 구획과 실제 파일명/크기/저장 상태를 표시한다. 시안 이미지를 UI로 쓰거나 가짜 파일 썸네일을 만들지 않았다.
- **문구/내용:** 대표 제목 14자·본문 77자는 원본과 같다. 메인 새 기안 비교에서 원본의 선택한 파일 1개는 첫 viewport 밖이며 구현은 새 파일 0개다. 파일 행은 저장된 모의 PDF 418KB와 긴 파일명 상태로 별도 확인했다. 브라우저는 영구 기기 보관을 주장하지 않고 현재 화면 메모리 보관 안내를 표시한다. 실제 updatedAt으로 서버 저장 시각을 표시하므로 원본의 09:40과 다르다. 삭제 경고·결과 확인과 상신 확인은 실제 앱의 계약/문구를 보존한다. 소스의 모든 number 필드에 ‘원’을 붙이는 가정은 적용하지 않았다.

## 실제 동작·상태 확인

- 일반 기안서의 제목/본문 입력과 시설장 1명 선택, 양식 선택, 지출 양식의 숫자/날짜/조건부 text/select/증빙 switch를 실행했다. 양식 변경 취소 후 숫자·날짜·조건부 입력·증빙 값을 보존했다.
- 회의록 2개 안건의 제목/내용 입력, 추가, 제거 확인 취소 후 입력 보존을 확인했다. 제거 확인과 이탈 확인에서 취소 또는 보관하고 나가기를 실행했다.
- 임시저장 검증 실패 후 제목·본문·선택을 유지하고 오류를 화면 위에 표시했다. 상신 취소 후 입력을 유지했다. 응답 유실 후 원 요청 결과 조회로 처리 결과 문서에 도달했다.
- 3초 지연 임시저장의 더블클릭은 모의 서버 POST 1회였다(`duplicate-request-proof.txt`). 요청 중 양식·결재자·파일·저장·상신을 잠갔다. 네트워크 전송 계층까지 항상 단일 요청을 보장한다고 주장하지 않는다.
- 본인의 DRAFT에만 삭제를 표시하고, 제목·첨부 개수·영구 삭제·미저장 입력·기기 보관본 폐기 경고를 확인했다. 취소/Escape는 문서를 보존한다. 응답 유실 시 입력을 유지하고 같은 삭제 요청 결과를 확인한 뒤 기안함 5→4건으로 복귀했다.
- RECALLED는 재상신 안내/행동이 있고 삭제가 없다. 양식 없음은 저장·상신을 막고, 결재자 없음은 상신만 막는다. 로딩·양식 오류·권한 오류·재시도를 실제 렌더로 확인했다. 권한 오류에서는 입력 폼을 표시하지 않는다.
- 360px 다크에서 40자 제목, 504자/여러 줄 본문, 긴 파일명 전문을 확인했다. 본문은 약 651px까지 자라고 전체 폼으로 스크롤한다. 다크 캡처는 DRAFT/긴 데이터이며 원본 크기·테마 보드의 새 기안과 동일 데이터에 대한 픽셀 비교로 주장하지 않는다.
- 360×800, 전체 200% 확대의 확인 경고는 본문만 스크롤하고 확인/취소 버튼을 유지한다. 별도의 300px 키보드 점유 상태에서 제목 입력과 세로 하단 행동이 접근 가능했다. 실제 네이티브 확인은 기존 Keyboard.dismiss를 사용한다.
- 접근 이름, 필수·오류 표시, radio checked 상태, 비활성 행동, 보이는 키보드 포커스, 취소 후 원 버튼 포커스 복귀를 확인했다. 최종 검수 탭 콘솔 error 목록은 비어 있었다.
