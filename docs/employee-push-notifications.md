# 직원 모바일 푸시 알림

푸시 설정을 켠 활성 직원의 유효한 모바일 로그인 기기에 발송한다. 작업자
본인에게는 그 작업으로 생긴 알림을 보내지 않는다. 퇴사일이 지났거나 비활성인
계정, 로그아웃한 기기, 알림을 해제한 기기는 제외한다.

| 상황 | 수신자 |
| --- | --- |
| 내 차례의 결재 요청 | 현재 결재자 |
| 결재 승인·반려·최종 완료 | 기안자 및 기존 대리결재 정책의 관련 결재자 |
| 결재 요청 회수 | 회수 당시 결재를 기다리던 결재자 |
| 24시간 이상 결재 대기 | 대기 중인 현재 결재자, 하루 한 번 |
| 새 직원 채팅 메시지·파일 | 받는 직원 |
| 새 할 일 배정·내용·기한 변경 | 현재 담당자 |
| 할 일 담당자 변경 | 새 담당자와 이전 담당자 |
| 배정한 할 일 완료·완료 취소·삭제 | 현재 ADMIN인 업무 배정자 |
| 오늘 마감·기한 초과 할 일 | 현재 담당자, 종류별 하루 한 번 |
| 자료실 새 게시물·내용·파일 변경 | 활성 직원 |
| 공용 업무 일정 등록·변경·취소 | 활성 직원 |
| 공용 업무 일정 시작 30분 전 구간 | 활성 직원 |
| 새 업무 기능 안내 | 활성 직원 |

마감·결재 대기 알림은 한국 시간 09:00–18:00에 생성한다. 공용 일정은
수동으로 등록한 업무 일정을 대상으로 하며 시작 30분 전부터 시작 전까지
생성한다. 정기 처리는 기존 Supabase 서버의 Cron에서 15분 주기로 요청하며 실행 지연이
발생할 수 있다. 즉시 알림은 요청 처리 후 발송하고, 실패하면 저장된 큐를
정기 처리에서 재시도한다. 완료되거나 삭제된 할 일, 읽은 채팅, 현재 결재
차례가 아닌 요청, 이미 시작한 일정, 이전 버전의 업무 변경 알림은 발송 전에
다시 확인해 제외한다.

잠금 화면에는 업무 종류만 표시하며 문서 제목, 대화 내용, 파일명, 청소년
정보는 넣지 않는다. 알림 선택 시 인증된 API가 현재 접근 권한을 확인한다.
업무 배정자의 할 일 상세는 본인이 배정한 업무만 읽기 전용으로 열 수 있다.
담당자 변경 후 이전 담당자의 알림은 개인 할 일 목록으로 이동한다.

운영 준비: PostgreSQL 마이그레이션을 적용한 뒤 서버를 배포하고, production
채널에 모바일 업데이트를 발행한다. `scripts/configure-mobile-push-cron.mjs`로 서버의 `MOBILE_PUSH_CRON_SECRET`을 Supabase
Vault에 저장하고 정기 실행 작업을 준비한다. `--activate`로 활성화한다.
운영 서버와 정기 작업에는 같은 푸시 전용 값을 설정한다. 자료실 정리의 `CRON_SECRET`은
변경하지 않는다. 기존 설치는 푸시 전용 변수가 없을 때만 `CRON_SECRET`을 사용한다.
비밀 값은 저장소에 기록하지 않는다. 기기의 알림 권한·방해금지·업무 프로필
일시 중지는 실제 소리나 배너 표시 여부에 영향을 준다.
