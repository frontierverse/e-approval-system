# 모바일 기안 작성 복구

이 문서는 새 기안·내 임시저장/회수 기안의 작성 내용 복구 범위를 설명한다. 서버의 임시저장 버튼은 기존과 같이 기안 문서를 저장한다. 기기 보관은 작성 도중의 입력을 복구하기 위한 별도 기능이다.

## 보관 내용과 계정

Android·iOS에서는 이미 설치된 Expo SecureStore를 사용한다. 제목, 선택 양식, 양식의 텍스트 입력, 결재자 ID, 정확한 문서·작성 세션 ID, 수정 기준 시각 및 원 저장 요청의 최소 증거만 보관한다. 첨부파일과 파일 이름·경로·업로드 URL·업로드 ID·로그인 토큰은 복구 레코드에 저장하지 않는다. 회의 안건은 기존 양식 입력 표현을 사용한다.

기기 보관의 상한은 레코드당 UTF-8 64KiB와 4개 작성 범위다. 초과하거나 저장소가 실패하면 현재 입력을 유지하고 보관 실패를 안내한다. 입력을 자르거나 다른 보관 내용을 자동 삭제하지 않는다. 서버의 기존 입력 한도를 기기 상한으로 줄이지 않는다. 브라우저에서는 메모리만 사용하므로 종료·새로고침 뒤 지속 복구를 제공하지 않는다.

앱을 다시 열었을 때 유효한 같은 계정 확인을 마친 뒤 복구 후보를 제공한다. 로그아웃, 확정된 인증 만료, 계정 교체는 기기 보관을 무효화한다. 문서 편집 권한을 확인할 수 없으면 해당 범위의 기기 본문을 제거하고 원 요청의 최소 증거만 남긴다. 현재 화면의 RAM 입력은 가린 채 보존할 수 있지만 렌더·업로드·저장·본문 체크포인트를 허용하지 않는다. 일반 연결 오류 동안에는 보관 내용을 유지하고, 확인 전에는 본문을 보여주지 않는다. 새 보존 기간이나 자동 만료 정책은 추가하지 않는다.

## 복구와 변경 충돌

기안함의 ‘작성 복구’ 또는 작성 화면에서 정확한 후보를 선택한다. 새 기안은 작성 세션 ID, 기존 기안은 본인 문서 ID에 연결된다. 복구 전에 최신 양식·결재자와 본인 편집 가능한 문서 상태를 확인한다. 제목·본문을 후보 목록에 미리 표시하지 않는다. 편집 불가 문서의 원 요청은 본문을 화면에 노출하지 않고 최소 증거로 결과만 확인한다. 최신 편집 조회가 거절되면 이전 화면의 입력과 파일을 가리고 저장·업로드를 막는다. 편집 불가 문서의 원 요청은 본문을 화면에 노출하지 않고 최소 증거로 결과만 확인한다. 최신 편집 조회가 거절되면 이전 화면의 입력과 파일을 가리고 저장·업로드를 막는다.

서버 내용이 바뀌면 기존 입력을 최신 기준에 적용하거나 서버 내용으로 교체하는 행동을 사용자가 선택한다. 양식의 안정된 필드 정의를 비교하며 오늘 날짜 같은 초기값은 양식 변경으로 취급하지 않는다. 비활성 양식이나 사용할 수 없는 결재자를 자동 전송하지 않는다. 버리기는 대상과 결과를 확인하고 실행한다.

## 응답을 받지 못한 저장

저장·상신의 요청 ID와 입력은 하나의 시도로 고정한다. 연결이 끊기거나 응답이 불완전하면 원 요청의 본인 처리 결과부터 확인한다. 결과를 확인하지 않고 새 키로 같은 기안을 만들지 않는다.

첨부 없는 원 요청의 전체 입력을 보유한 경우에만 동일 요청을 명시적으로 재시도할 수 있다. 첨부 포함 요청 또는 기기 용량 때문에 최소 증거만 보관한 요청은 앱 재시작 후 결과 확인만 제공한다. 파일 정보를 빼서 다른 요청을 보내지 않는다. 결과 조회의 404는 저장되지 않았다는 증거로 사용하지 않는다.

처리 완료가 확인된 뒤 화면 재조회나 기기 정리에 실패하더라도 저장 실패로 표시하거나 자동 재전송하지 않는다. 저장 이후 새로 입력한 내용은 이전 요청의 완료 응답이 지우지 않는다. 후속 입력을 계속 작성할 때는 확정된 결과 기안의 최신 기준에 적용하거나 별도 새 기안으로 옮기는 행동을 직접 선택한다. 대상 범위의 보관과 읽기를 확인한 뒤 이동하며, 이 행동으로 서버 저장 요청을 자동 전송하지 않는다. 후속 입력을 계속 작성할 때는 확정된 결과 기안의 최신 기준에 적용하거나 별도 새 기안으로 옮기는 행동을 직접 선택한다. 대상 범위의 보관과 읽기를 확인한 뒤 이동하며, 이 행동으로 서버 저장 요청을 자동 전송하지 않는다.

## 서버 계약

- 기존 저장 응답의 `documentId`, `status`, `updatedAt`은 유지한다. 새 앱을 위한 `proof`에 원 요청 ID·의도·원 문서 ID·처리 문서 ID·처리 시각·처리 당시 수정 시각을 추가한다.
- `GET /api/mobile/drafts/requests/[requestId]`는 본인 요청의 최소 처리 증거만 반환한다. 기존 문서 요청은 `documentId` query로 원 범위를 지정한다. 본문·제목·첨부·원 감사 로그는 반환하지 않는다.
- 현재 문서의 시각과 처리 당시 시각을 구분한다. 삭제된 문서의 감사 대상 ID를 증거로 사용하며 같은 키로 문서를 다시 만들지 않는다. 과거 감사에 충분한 증거가 없으면 추정하지 않는다.
- 옵션·목록·상세·요청 상태 조회는 최신 ACTIVE 계정을 같은 트랜잭션에서 확인하고 읽기만 수행한다. 조회에서 업로드 정리를 실행하지 않는다.
- 본문은 기존 300,000 JavaScript 문자 한도와 별도로 UTF-8 1,200,000 byte 및 10초 읽기 한도를 적용한다. 중복 JSON key, 잘못된 UTF-8, 알 수 없는 입력을 거절한다.
- 새 테이블·마이그레이션·Cron·서버 복구 본문 저장소는 없다. 기존 결재 정책과 파일 저장 경로를 재사용한다.

## 검증 범위

실제 제품 소스에 주입한 합성 저장소·HTTP·계정 fixture로 작성 중단, 저장소 장애, 계정·화면 변경, 충돌 및 원 요청 확인을 검사한다. CI의 고정된 일회용 PostgreSQL에서 병렬 동일 요청, 업무·감사 원자성, 삭제 후 증거 및 최신 권한/CAS를 검사한다. 운영 업무 문서를 테스트로 생성하지 않는다.

네이티브 번들과 게시 자산의 정확한 런타임·해시는 배포 시 별도로 검사한다. 합성 저장소와 RN Web 검수를 실제 기기의 Keychain/Keystore 내구성·OS 잠금·강제 종료 검증으로 해석하지 않는다.
