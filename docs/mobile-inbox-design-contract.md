# 바자울 받은결재 디자인 최신 기능 계약

기준: 운영 main **17e4addc06ab50ea82346b9326d47adafb255502**, 2026-10-05. 아래 내용은 실제 소스에서 확인한 기능과 새 디자인의 검수 기준이다. 첨부 받은결재 캡처는 실제 Expo 화면에 합성 응답을 연결한 기능 참고이며 실제 운영 문서가 아니다.

## 실제 진입과 API

Expo 탭 `/inbox`, 홈의 받은결재 전체 보기 → 목록 → `/documents/[id]` 기존 상세. 탭 보호는 `user.canApproveDocuments===true`, API 보호는 활성 직원 세션과 현재 직급 시설장 검사다. role=ADMIN은 직급 검사나 결재선 소유 조건을 대체하지 않는다.

`GET /api/mobile/inbox?q=&dateFrom=&dateTo=&sort=latest|oldest&page=1`. 허용 조건은 이 다섯 가지다. 서버는 folder/status/userId를 받은결재 조건으로 사용하지 않는다. 기존 목록 범위는 문서 상태 SUBMITTED/IN_PROGRESS와 본인 PENDING 단계의 교집합이다. **본인 PENDING이 곧 현재 결재 차례라는 뜻은 아니다.**

검색은 앞뒤 공백 제거, 최대 100자, 제목·문서번호·분류·기안자 이름의 대소문자 무시 부분 검색이다. 기간은 실제 YYYY-MM-DD이고 양 끝 선택, 시작≤끝. 한국 날짜의 시작 00:00:00부터 종료 23:59:59.999까지 포함하며 submittedAt이 없으면 서버가 createdAt으로 조회한다. 정렬은 상신일→작성일→id의 안정적 최신/오래된순이고 상신일 null은 마지막이다.

```json
{
  "total": 23,
  "page": 1,
  "pageSize": 20,
  "totalPages": 2,
  "documents": [{
    "id": "qa-inbox-1",
    "documentNo": "EA-2026-0147",
    "title": "10월 프로그램 운영비 지출결의",
    "status": "submitted",
    "submittedAt": "2026-10-05T00:12:00.000Z",
    "drafterName": "김예시",
    "stepOrder": 1,
    "attachmentCount": 2
  }]
}
```

위 JSON은 **응답 필드 형태만 보여주는 합성 발췌**다. 실제 메인 모의에서는 1페이지에 20행, 2페이지에 3행이 있어야 한다. total은 현재 필터 결과, pageSize는 항상 20, totalPages는 최소 1이며 요청 page가 범위를 벗어나면 서버가 마지막 페이지로 보정한다.

## 없는 정보와 허용되는 표시

| 정보 | 계약 |
| --- | --- |
| 제목·문서번호·상태·기안자·상신 시각·첨부 개수 | 응답으로 표시 가능 |
| 본인 대기 단계 순서 stepOrder | 전체 단계 수/현재 차례/즉시 승인 가능을 뜻하지 않음 |
| 분류명 | 검색 대상이지만 행 응답에 없음. 행 분류 칩/별도 분류 선택 자료로 만들지 않음 |
| 현재 결재자·전체 결재선·canDecide·본문·반려 사유·첨부 파일명 | 목록에 없음. 기존 상세에서 확인 |
| 긴급·기한·오늘 마감·미처리 일수·금액·읽음·즐겨찾기 | 목록 API와 업무 규칙에 없음 |
| 전체 대기와 필터 결과의 두 총수 | 단일 total뿐임. 필터 중 별도 전체 총수로 표시하지 않음 |
| 알림 배지 | 별도 알림 기능의 안 읽음 건수. 모의 3건은 받은결재 건수와 무관 |

문서번호는 빈 문자열, 상신 시각은 null, 단계는 null일 수 있다. 없는 값을 문서번호·시각·진행률로 만들지 않는다. API 작성일 fallback은 검색 조건용이며 createdAt은 목록 응답에 없으므로 화면 날짜로 대체할 수 없다.

## 현재 앱의 실제 동작

검색어 q와 시작/종료 날짜, sort, page는 Expo Router 매개변수로 보존한다. 검색/기간 적용과 정렬은 page=1로, 페이지 이동은 다른 조건을 유지하며 변경한다. 초기화는 q·기간을 지우고 latest/1로 돌아간다. 검색은 엔터 또는 검색 버튼, 기간 오류는 시작일 입력으로 포커스를 보낸다. 기간은 기본 닫힌 펼침 영역이고 적용/기간 지우기를 지원한다.

`useFocusedPage`는 탭 포커스/재방문·경로 변경·당겨서 갱신에 재조회하며, 응답 순서를 식별해 늦은 요청이 최신 결과를 덮어쓰지 않게 한다. 다른 조건의 기존 결과는 숨기고 같은 조건의 재조회 때는 기존 결과가 남을 수 있다. 목록 행은 제목과 기안자·상신 시각·첨부 개수로 상세를 연다. 최초 로딩은 3개 조밀한 행이며 0건/검색 0건/최초 오류/기존 결과 오류/재시도/페이지 경계를 구분한다.

## 새 디자인에서 명확히 해야 하는 상태

아래는 현재 표시를 무조건 복제할 요구가 아니라 **새 시안의 안전·가독성 기준**이다. 운영 코드 수정은 후속 구현 단계에서 검증한다.

- 적용 전 검색/기간과 적용된 조건을 분리하고, 취소 때 적용 상태를 유지한다. 오류가 있어도 작성한 조건을 보존한다.
- 같은 조건 재조회 오류에서는 이전 목록임을 표시하고 재시도한다. 권한 거절/세션 만료/계정 변경에서는 이전 목록을 제거한다. 과거 건수를 최신 정보처럼 단정하지 않는다.
- 기존 상세에서 문서 처리 후 돌아오면 같은 조건을 재조회하고 행 제거·마지막 페이지 보정을 반영한다. 상세 화면의 업무 행동을 목록에 복사하지 않는다.
- 새로고침·검색·기간 적용·정렬·페이지 이동의 요청 대기/중복/늦은 응답을 구분한다. 키보드가 열린 상태에도 제출/취소/오류가 접근 가능해야 한다.
- 받은결재에는 상태별 완료 이력이나 임시저장 탭을 추가하지 않는다. 목록 밖 화면은 모의 목적 안내/기존 디자인 재사용까지만 한다.

## 시각 체계와 소스 근거

실제 앱의 공용 `HomeTheme`를 이어간다. 라이트는 background #F7F8FA, surface #FFFFFF, text #191F28, secondary #5C6675, muted #647084, divider #E8ECF1, controlBorder #86909E, accent/action #2563EB, accentSoft #EDF4FF다. 다크는 background #11151B, surface #1C222B, text #F4F6FA, secondary #AFB8C7, muted #A4AEC0, divider #303947, controlBorder #647084, accent #8DB7FF, actionFill #2563EB, accentSoft #202F49다. divider를 입력 경계/포커스로 그대로 쓰지 않는다. Feather 선형 아이콘, 4/8/12/16/24 간격, 44px 이상 조작 대상과 Safe Area를 사용한다.

탭바는 아이콘 5개이고 선택 아이콘의 절제된 강조, 접근 이름과 알림 배지를 유지한다. 시각 라벨은 현재 탭바에 없지만 접근 이름은 홈/받은결재/문서함/알림/내 정보다. 기존 페이지와 일관된 52px 안팎의 작은 헤더, 반복 행/얇은 구분선, 무리한 줄임 없이 긴 제목/큰 글자 대응을 우선한다.

근거 소스: `mobile/src/components/inbox-screen.tsx`, `inbox-list.tsx`, `mobile/src/lib/inbox.ts`, `use-focused-page.ts`, `home-theme.ts`, `types.ts`, `mobile/src/app/(tabs)/_layout.tsx`, `src/app/api/mobile/inbox/route.ts`, `src/lib/mobile-inbox.ts`, `mobile-inbox-core.ts`, `mobile-document-library-core.ts`, `tests/mobile-inbox.test.mts`.

설계/브라우저 시안의 검수와 실제 iOS·Android 설치본의 OS 키보드·동적 글자·스크린리더·운영 데이터 연결은 서로 다른 검증이다. 미확인 실기기 항목은 완료로 표시하지 않는다. 제공한 source/API 설명에는 운영 인증 값·실제 업무 자료가 포함되어 있지 않다.

## Claude v1 구현 반영 — 2026-10-05

앞의 ‘현재 앱의 실제 동작’은 Claude 전달 당시 main 17e4add의 기록이다. 후속 구현은 작은 60px 헤더, 검색·기간·정렬, 연결된 84px 이상 목록 행을 사용한다. 제목·상태·기안자·한국 상신 시각(연도 포함)·문서번호·첨부 개수를 표시하며 단계 2 이상에만 ‘내 결재 단계 n’을 표시한다. 분류는 검색에만 쓰고 행에 추가하지 않는다. 초기 로딩은 같은 밀도의 6개 행이다.

기간 오류는 잘못된 시작일/종료일로 포커스를 보내고 값을 보존한다. 취소/Escape는 적용된 기간과 실행 버튼 포커스로 돌아온다. 네이티브 키보드가 열린 동안 기간 취소·적용 도구를 키보드 위에 두고 받은결재 탭바를 숨긴다. 작은 화면/큰 글자에서는 날짜와 컨트롤을 필요한 만큼 줄바꿈하고 종료일의 실제 위치로 스크롤한다.

조회 결과·오류·대기 상태는 계정/세션과 경로에 묶인다. 같은 조건의 연결 실패는 실제 마지막 조회 시각과 이전 결과를 유지하고, 다른 조건 실패는 이전 결과를 표시하지 않는다. 401/403은 기존 목록을 제거하고 검색 입력·목록 대신 접근 안내를 표시한다. 세션 401은 기존 세션 처리에 따라 로그인으로 이동한다. 빠른 새로고침은 동시에 한 요청만 실행하며 늦은 응답은 현재 결과를 바꾸지 않는다.

서버가 보정한 페이지를 URL에 반영하고 안내한다. 이후 총 페이지 수가 달라지면 오래된 보정 안내를 표시하지 않는다. 기존 상세에서 돌아온 뒤 현재 조건을 재조회하는 흐름은 유지한다. 검수 결과와 미확인 실기기 항목은 design-qa.md에 기록한다.
