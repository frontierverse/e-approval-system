# Claude Design 전달 바자울 모바일 내 정보 v1

기준일 **2026-10-05 한국시간**, 운영 main **44f09062af518976e7cd9eedaa5333fa2aced4d0 / PR #28**. 홈 v2·문서함 v1·문서 상세 v1·기안 작성 v1·받은결재 v1·알림 v1은 실제 앱과 Android·iOS 운영 OTA에 적용했다. 기존 Claude 작업 **바자울 전자결재 앱 디자인**에 일곱 번째 페이지 **내 정보 v1**을 추가한다.

## 목적과 범위

직원이 현재 로그인 계정을 확인하고, 업무 메뉴와 계정·도장 설정·앱 업데이트로 빠르게 이동하며, 이 기기의 결재 알림을 설정하고 안전하게 로그아웃하는 허브를 만든다. 기존 HomeTheme와 Feather 선형 아이콘을 이어간다. 완료한 여섯 페이지는 보존한다.

이번 범위는 **내 정보 허브 한 화면**이다. 계정·도장 편집, 비밀번호 변경, 앱 업데이트 상세, 채팅·청소년 관리·자료실·급식·카페·업무일지·업무 일정 내부를 새로 설계하지 않는다. 링크는 기존 화면으로 이동하는 모의 연결로 검토한다. 실제 운영 API·로그인·직원 정보·청소년 정보·도장 이미지·푸시 등록·앱 소스·DB·배포는 사용하거나 변경하지 않는다. 합성 자료와 모의 상태만 쓴다.

첨부 01은 이 브리프, 02는 필수 UI/UX 기준, 03은 최신 기능 계약, 04·05는 실제 적용된 홈·알림 스타일, 06·07은 현재 내 정보의 기능 참고 캡처다. 최신 계약이 과거 시안의 가정보다 우선한다. 06·07은 합성 계정으로 실행한 **현재 Expo 웹 화면**이다. 웹에서는 기기 알림 행동이 없으므로, 이 캡처를 모바일 앱의 알림 설정 상태 전체로 해석하지 않는다. 기존 내 정보의 남색 아이콘·중앙 정렬은 기능 참고이며 새 시안은 적용된 HomeTheme를 따른다.

## 첫 화면과 정보 구조

짧은 **내 정보** 제목, **이예시 · 시설장** 계정 요약, 바로 이어지는 업무 메뉴가 첫 화면의 중심이다. 소개·환영·거대한 아바타·설정 설명으로 상단을 채우지 않는다. 가짜 업무 지표를 추가하지 않는다. 업무 메뉴 첫 행이 기본 390×844의 Safe Area와 전역 탭바를 제외한 콘텐츠 상단 40% 이내에서 시작하도록 한다.

업무 메뉴는 약 44~56px 높이의 간결한 한 줄 탐색 행을 시작점으로 삼고, 의미 있는 그룹 표면과 구분선을 쓴다. 업무 데이터 목록의 64~88px 기준을 짧은 설정 링크에 기계적으로 적용하지 않는다. 기본 글자에서 계정 요약과 여섯 업무 메뉴, 설정 링크의 시작을 빠르게 훑을 수 있게 한다. 44×44px 이상의 상호작용 영역을 지키며 큰 글자에서는 줄바꿈·높이 확장을 허용한다. 알림 상태 안내가 길어지면 실제 정보량에 따른 세로 스크롤을 허용한다.

계층은 **현재 계정 → 업무 기능 → 계정·앱 설정 → 기기 알림 → 로그아웃**이다. 알림 설정 오류는 해당 섹션에서 행동과 함께 보여주며 다른 업무 메뉴를 가리지 않는다. 로그아웃을 가장 강한 주 행동으로 강조하지 않는다.

## 계정과 메뉴

허브가 가진 사용자 정보는 `id`, `name`, `role`, `positionName`, `canApproveDocuments`다. 이름과 직급만 표시한다. 부서·이메일·프로필 사진·도장·계정 상태·기기 목록·권한 요약을 추측하거나 새 조회로 끌어오지 않는다. 필요하면 합성 이름의 초성 표식을 작게 쓸 수 있지만 실제 사진처럼 만들지 않는다. 긴 한글 이름과 직급에서도 잘림·겹침이 없어야 한다.

다음 여섯 업무 메뉴의 명칭·순서·목적지를 유지한다. 메뉴별 별도 설명, 거대한 타일, 새로운 업무 통계는 필요하지 않다.

| 행 | 기존 목적지 | 표시할 상태 |
| --- | --- | --- |
| 직원 채팅 | `/chat` | 본인 안 읽음 수 또는 확인 중/확인 필요 |
| 청소년 관리 | `/youth` | 기본 탐색 행 |
| 자료실 | `/resources` | 기본 탐색 행 |
| 급식·카페 | `/meal-menu` | 기본 탐색 행 |
| 업무일지 | `/work-logs` | 기본 탐색 행 |
| 업무 일정 | `/work-schedules` | 기본 탐색 행 |

그 뒤 **계정·도장 설정** → `/account`, **앱 업데이트** → `/app-updates`를 제공한다. 자식 화면의 입력 폼이나 앱 버전·런타임·배포 ID를 허브에 새로 노출하지 않는다. 현재 허브에는 업데이트 가능 여부를 표시할 계약이 없다. 확인 없이 업데이트 배지나 ‘최신 버전’을 만들지 않는다.

채팅 안 읽음 수는 결재 알림 탭의 배지와 별개다. 0이면 기본 메뉴, 1~99는 실제 수, 100 이상은 **99+**로 표시하되 접근 이름에는 실제 수를 전달한다. `null`은 0이 아니다. 아직 조회 전이면 **확인 중**, 실패이면 **확인 필요**다. 계정 변경·세션 만료 뒤 이전 계정의 이름·건수·메뉴 대상이 남으면 안 된다.

## 기기 알림

이 섹션은 **현재 로그인 세션의 이 기기 푸시 등록**을 조작한다. OS 알림 권한은 별개다. 서버의 등록 값이 켜짐이어도 OS 권한이 꺼졌다면 수신 가능한 상태로 단정하지 않는다. 다른 기기의 등록을 전부 켜거나 끄는 설정이 아니다. 결재 알림 목록의 읽음 상태나 채팅 안 읽음 수를 바꾸지 않는다.

현재 상태를 짧은 문구와 다음 행동으로 알려준다. 바로 켜짐/꺼짐을 바꾸는 낙관적 스위치는 피하고, **서버 확인 뒤 상태 확정**과 **처리 중 잠금**을 표현한다. 스위치를 시각적으로 쓰더라도 미확인·권한 거부·실패를 거짓 OFF로 표현해서는 안 된다.

| 모의 상태 | 표시와 행동 |
| --- | --- |
| 최초 확인 중 | ‘알림 설정 확인 중…’, 가짜 OFF나 켜기 행동을 만들지 않음 |
| 확인된 꺼짐 | ‘이 기기에서 알림 받기’ |
| 켜기 처리 중 | ‘설정 중…’ 등 해당 작업 표시, 설정 행동 중복 실행 방지 |
| 확인된 켜짐 + OS 허용 | 등록된 상태 안내와 ‘이 기기 알림 끄기’ |
| OS 권한 꺼짐 | 권한 안내, ‘기기 알림 설정 열기’, ‘알림 등록 다시 시도’; 등록값이 켜짐이면 끄기 행동도 유지 가능 |
| 등록·조회 실패 | 마지막 확인 상태 또는 미확인을 유지, 해당 실패 설명과 ‘알림 설정 다시 시도’ |
| 끄기 실패 | 아직 켜짐, 실패를 안내, 재시도는 **끄기**를 재시도하며 다시 켜기 작업으로 바꾸지 않음 |
| 완료 | ‘이 기기에서 결재 알림을 받습니다.’ 또는 ‘이 기기의 결재 알림을 껐습니다.’의 짧은 피드백 |
| 웹 | ‘설치한 모바일 앱에서 설정할 수 있습니다.’, 모의 네이티브 상태와 명확히 구분 |

OS 권한 요청은 사용자가 켜기를 눌렀고 요청 가능한 미결정 상태일 때만 한다. 이미 거부된 권한을 반복 팝업으로 요청하지 않는다. 기기 설정을 연 사실만으로 성공시키지 않는다. 앱으로 복귀하면 상태를 다시 확인한다. iOS의 provisional/ephemeral 허용을 임의로 거부 상태로 표현하지 않는다.

알림 설정 도중 업무 메뉴는 계속 사용할 수 있다. 겹치는 알림 설정은 하나의 작업으로 합치며, 현재 계정이 아니게 된 응답으로 상태·메시지·화면 이동을 갱신하지 않는다. 실패한 끄기 의도는 자동 재조회로 사라지지 않는다. 프로토타입은 이 동작을 모의로 검토하고 실제 OS 설정·권한·푸시 API를 호출하지 않는다.

## 로그아웃

설정 이후에 **로그아웃**을 배치한다. 모바일 기존 확인은 제목 ‘로그아웃’, 본문 **이 기기에서 로그아웃하시겠습니까?**, 취소와 로그아웃 행동이다. 취소하면 그대로 유지한다. 확인 시 한 번만 실행하고 처리 중 연타를 막는다. 이 중복 실행 잠금은 새 시안의 안전 기준이며 현재 허브에 이미 구현됐다는 뜻은 아니다.

현재 서비스는 로컬 세션과 이전 계정의 private 상태를 먼저 정리한다. 서버 로그아웃 통신 실패가 이전 계정 정보를 되살리는 성공/실패 흐름이 되어서는 안 된다. 모든 기기 로그아웃, 계정 삭제, 서버 문서 삭제를 뜻하지 않는다. 웹 검토용 프로토타입에서도 확인 창을 모의로 제공하되 현재 앱의 웹 구현은 즉시 로그아웃하는 차이를 기록한다. 실제 로그아웃이나 인증 정보 입력은 하지 않는다.

## 탭바·시각 언어·접근성

시설장: **홈 → 받은결재 → 문서함 → 알림 → 내 정보 선택**. 일반 직원과 시설장이 아닌 관리자: **홈 → 문서함 → 알림 → 내 정보 선택**. 받은결재 여부는 `canApproveDocuments`로 정하고 역할 문자열만으로 추측하지 않는다. 결재 알림 배지는 기존 1~99/99+ 규칙과 실제 수 접근 이름을 유지한다. 0·미확인은 배지를 숨기지만 같은 확정 상태라고 설명하지 않는다.

흰/어두운 그룹 표면, 얇은 경계, 절제된 파란 선택·주 행동, Feather 선형 아이콘과 기존 탭 선택 배경을 보존한다. 실제 OS 상태바를 장식으로 이중 생성하지 않는다. 새로운 테마 선택·생체 인증·PIN·2FA·알림 카테고리·기기 관리·약관·개인정보 메뉴를 발명하지 않는다.

최소 44px 터치 영역, 논리적인 제목·탐색·접근 이름, 보이는 키보드 포커스, 읽기 순서, 일반 글자 4.5:1 대비를 지킨다. 긴 이름·직급·99+·오류 문구와 200% 글자에서 읽기와 안전성을 우선한다. 모달은 포커스 진입·내부 이동·Escape/취소·실행 요소로 복귀를 검토한다. 프로토타입의 상태·테마·권한·네트워크 컨트롤은 **앱 화면 밖**에 둔다.

## 합성 자료와 산출물

메인: 390×844 라이트, **이예시 · 시설장**, 채팅 **안 읽음 3개**, 결재 알림 탭 배지 **3**, 내 정보 선택, **네이티브 알림 등록 꺼짐·OS 요청 가능**. 일반 직원 **김예시 · 직원 / canApproveDocuments=false**의 4탭 변형도 제공한다. 이 이름과 수는 모두 합성 자료이며 첨부 웹 기능 캡처의 채팅 0건과 달라도 정상이다.

추가 상태: 채팅 0/확인 중/확인 필요/128개, 긴 이름 ‘김아주긴이름예시직원’과 긴 직급, 알림 최초 로딩·켜짐·권한 거부·등록 실패·끄기 실패와 그 재시도·OS 설정 열기 실패·앱 복귀·중복 실행·계정 전환·세션 만료·웹 미지원, 로그아웃 취소·처리 중·완료·늦은 응답 무시를 다룬다. 실제 서비스에 없는 기능은 추가하지 않는다.

완성된 **내 정보 v1** 페이지, 대표 캡처, 주요 상태 캡처, 동작하는 검토용 프로토타입, 편집용 소스 ZIP, 검수 결과를 제공한다. ZIP 이름은 `bajaul-profile-v1-source.zip`를 권장한다. 기존 페이지를 재작성하지 말고 허브와 검토 컨트롤만 추가한다.

## 완료 검수

- 390×844·360×800, 라이트·다크, 200% 상당 큰 글자를 실제 렌더로 확인한다. 가로 넘침, 글자·행동 겹침, 탭바 가림, 44px 미만 영역이 없어야 한다.
- 첫 화면에서 로그인 계정과 업무 메뉴를 바로 확인하고 기본 첫 업무 행이 콘텐츠 상단 40% 이내에서 시작해야 한다. 오류 때문에 메뉴가 사라지면 안 된다.
- 여섯 메뉴의 이름·순서·목적지, 두 설정 링크, 4/5탭과 내 정보 선택, 채팅 수와 결재 알림 수의 독립성을 확인한다.
- 미확인을 꺼짐/0으로 단정하지 않고, OS 권한과 등록 상태를 구분하며, 실패한 끄기 재시도가 실제 끄기 의도를 유지하는지 확인한다.
- 처리 중 중복 실행 방지, 늦은 응답과 계정·세션 변화의 이전 정보 제거, 모의 로그아웃 취소·확인 및 모달 포커스를 확인한다.
- 결과에 검수 경로·크기·첫 화면에서 보이는 정보·가로 넘침 여부·실제로 검토한 상태를 기록한다. DOM 검수·모의 OS 상태와 실제 iOS/Android·기기 글자·스크린리더·운영 API·푸시 검증을 구분한다. 실기기 미확인은 그대로 적는다.
